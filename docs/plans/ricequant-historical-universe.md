## 逐日覆盖与失败边界

同日共享因子收益和协方差；个股载荷、特异收益、特异风险分块请求。只有三项完整有效的证券进入三个个股表，三表使用同一完整交集。覆盖表保留所有已知身份候选，不能为提高覆盖率删去缺失证券。

状态以迁移 [048](../../packages/gr-db/src/gr_db/ddl/postgres/048_factor_model_run_coverage.sql) 为准：

| 状态 | 含义 |
| --- | --- |
| `included` | 三项个股数据完整有效 |
| `provider_not_returned` | 有效请求成功完成，三项均未返回；原因未确认 |
| `partial_bundle` | 仅部分个股接口返回，保留缺失项 |
| `unmapped_symbol` | 证券身份已知，但无法生成请求代码；不是身份未知 |
| `sdk_filtered` | 身份已知，但 SDK 未接受任何候选代码，未发个股请求 |
| `universe_boundary_unknown` | 上市／退市边界未确认，未发个股请求 |

后三项必须 `request_code=NULL`、三项 `pieces` 全为 false；被过滤或无法转换的输入保留在 `input_codes` 与证据中。前三项须有实际请求代码，`pieces` 与状态一致。

单股未返回或部分返回可形成降级日；停牌、ST、新上市和退市本身不等于正常不覆盖。认证、配额、网络失败，非法数值，日期／因子轴异常，协方差或因子收益缺失、R2 失败、没有任何完整股票仍阻断整日，不能伪装成普通缺失。未知质量问题或大幅覆盖下降应暂停检查，各模型不互相补值。

`invalid_value` 只保留 raw 失败证据；真正无法解析身份的代码留 raw `unresolved_identity`，解决前禁止入库；`unsupported_exchange` 属范围排除证据。三者均不是覆盖表状态。

**已确认的试行资格门槛**：`candidate > 0` 且 `complete * 1000 >= candidate * 999`，身份及上市边界未知为 0。覆盖不足但数值合法的 production 整包可留库，标 `publication_eligible=false` 后停止批次；达到门槛仍需通过发布程序，不等于已发布。

## 身份、存储与重放

- 固定名单保留 v1 合约，仍要求每份个股数据完整覆盖配置名单；旧 `listed_cn_a_v1` 保留原规则重放，production 仅支持 `listed_cn_a_v2`。v2 variant 包含用途、模型、行业、期限、源单位证据及名单／映射规则版本，不包含每天变化的股票列表；每日 manifest 保存候选、快照与哈希。
- 原始响应及观察不可变；名单规则、单位或用途变化生成新身份／观察，不改旧 raw 或 run。模型和因子顺序复用现有 `factor.*` 表，不按三个模型复制表结构；跨模型比较使用共同日期和完整证券集，并展示覆盖差异。
- `factor.model_run_coverage` 以 `(run_id, instrument_id)` 保存逐股结果。逐股 `evidence` 只含该证券的日期边界、SDK 映射或缺失原因；完整名单与参考快照留 raw，共用规则、SDK 版本和哈希摘要进入 run／ETL，不逐股复制。
- 迁移 [049](../../packages/gr-db/src/gr_db/ddl/postgres/049_risk_import_receipts.sql) 将五件套与覆盖表作为单一逻辑目标 `factor.risk_bundle`。业务数据、覆盖、receipt、binding、DB 检查点及成功 ETL 同日事务提交，capture 独立保留；观察级双水位不能用最大日期冒充连续完成。
- 同观察、同 importer 重放核验收据／绑定／检查点后跳过业务写入；同 raw 换 importer 版本不允许重新绑定。已完成批次保留原 `importer_version`，新批次按其版本策略登记，不能从当前 Git 自动改写历史。
- CLI 退出码 `4` 表示已提交但资格不足；`5` 表示事务退出异常后暂停，须核对结果已确认提交还是仍未知，不能一概宣称回滚。恢复及显式观察选择见 [gr-data 使用说明](../../packages/gr-data/README.md#风险观察的显式选择与修复追溯)。

历史存储与配额测量留在[验收记录](../history/2026-10-23-rq-risk-validation.md)，不再作为当前容量或剩余下载时间。后续批次按实际名单、启动／参考开销、重试和共享账号消耗重新预算，预留 10% 额度；计数延迟或跨午夜重置时，不能把零增量视为零消耗。现有专用执行器的配额／质量暂停仍须人工复核恢复，不能因次日额度重置自动续跑。

正式读取仍待 [D-022](../../.agents/brain/DECISIONS.md#d-022) 的 2b 落地，须满足：

1. 发布清单逐项钉住组成收据及米筐具体 `run_id`；五张业务表与覆盖表同 run，日期、模型、行业体系及因子顺序一致。清单缺失、未发布或未包含所需项时返回 unavailable，不接受任意 run 覆盖，也不回退最新或旧固定样本。
2. 发布拒绝 validation，数据库约束／触发器也须拒绝绕过应用的直接 INSERT；同时消费 `risk_bundle_publishable` 禁用证据，永久排除 REAL 问题旧 run，按明确替代 ID 选择已验收观察，不能推断“最新就是替代”。
3. 一期只诊断最新日，暂不建可变数据版本表。任一组成当前收据变化，旧版本标为 revised／不可复算，与组成写入原子衔接；统一读取在同一一致性快照内复核收据。行情、估值等所有读取组成均需接入，未接入的能力不发布，缓存不得复用已修订／撤销版本。
4. 取数以发布时刻为截止，不能用 `now()`；该过滤不能恢复被 UPSERT 覆盖的数据。已有报告仅作为历史计算产物展示并标明修订状态，不承诺历史复算。
5. 发布资格与校准分别判断。允许发布的未校准 run 仍为 `calibrated=false`，相关指标 degraded；研究显式选择验证 run 时保留“验证／未发布”标识及 run 清单，不进入正式诊断版本或缓存。诊断专用 DB 角色延后。

## 持仓诊断如何消费降级日

以下为待 2b 统一读取实现的契约。按 [D-017](../../.agents/brain/DECISIONS.md#d-017)，从完整输入持仓及原始权重出发，按清单 run 左连接覆盖与个股数据，不从 exposure 反向生成持仓集合。

| 覆盖情况 | 诊断行为 |
| --- | --- |
| `included` 且三项完整 | 使用指定 run；未校准或批准的覆盖降级保留 degraded 原因 |
| 未返回、部分缺失或身份未解析 | 保留持仓、原始代码、权重和来源状态，相关指标为无 value 的 `UnavailableMetric`，不填零、不估算、不跨日／模型补值 |
| 覆盖表无该持仓 | 覆盖未知／不可用，不推断零风险或正常不覆盖 |
| `included` 但缺明细、日期／run 不一致 | 完整性异常，阻断相关计算，不能按普通降级消费 |

同时展示按股票数及原始持仓权重计算的覆盖范围，分母保留全部持仓。任一所需非零持仓缺失，完整组合风险及完整风险贡献 unavailable；独立指标可单独计算。若展示已覆盖子集分布，只在已知子集内归一化，明确子集范围、degraded 及原组合覆盖权重，继续展示未覆盖持仓。

全市场覆盖率达标不替代组合检查：80% 权重有数据、20% 缺失时，覆盖权重为 80%，完整组合风险仍不可用。

## 剩余顺序与验收

2b 方案评审可在等待源盘期间开展；迁移对账是本机真实数据联调的前置。后续增量不以 2b 完成为采集前提，正式诊断读取须等待发布验收。

| 顺序 | 剩余任务 | 通过条件 |
| --- | --- | --- |
| 1 | 按迁移计划恢复并对账已完成历史 | 源盘带回后复制 raw／账本／证据，以 PG 逻辑备份恢复；核对三模型逐日 raw、run、收据、绑定、覆盖与双水位，保留 validation、失败观察、禁用记录和替代关系，不重启已完成执行器 |
| 2 | 评审 2b 发布与读取方案及 DDL | 明确清单、全部组成写入的收据／失效协议、缓存状态和一致性读取；复用 049，不将其直接泛化为所有供应商收据；DDL 仅在 gr-db 新增迁移，先隔离验证再按授权执行工作库迁移 |
| 3 | 实现并验收 2b，再独立发布 | 验证直接 SQL 引用 validation 被拒、禁用 run 被拒、指定 run 六表一致；组成变化与版本失效原子，后续新 run 不偷换原清单；收据不符或版本已修订时拒绝重算和缓存复用；80%／20% 持仓用例保留全部权重且组合风险不可用 |
| 4 | 安排后续增量及正式运行 | 在迁移和相关可靠性门禁通过后，另定结束日、版本与账号预算；遇新质量问题暂停，成功 raw 不重复抓取，正式风险读取仅在 2b 完成并发布后开放 |

动态名单与恢复的回归边界继续保留：上市首日、退市边界、后来退市证券、历史换码、SDK 过滤、未知身份、停牌、单接口缺失、空响应、数值／协方差失败、配额中断及重复观察。断言所有候选有去向、三张个股表同一完整交集、失败日无半套业务数据、模型互不补值、观察时间真实。

通用 B1／B2、租约、调度与备份按 [gr-data 可靠采集计划](gr-data-reliability-implementation-plan.md) 推进；它们与诊断发布各有验收边界。本次仅精简文档，不启动采集、工作库迁移或正式读取。
