# 米筐全市场历史名单与覆盖设计

读者：数据平台维护者及诊断取数实现者。用途：确认全市场历史回补与消费规则。状态：2026-10-23 用户已认可动态名单、逐股覆盖及降级日保存的设计方向；本版补充起点、run 隔离、下游读取和流量估算，**待用户复核后才实施 DDL／代码**。正式覆盖阈值等独立全市场样本后再定。

固定 100 股验证已于 2026-10-22～23 完成：三个模型各 676 个交易日、共 2,028 个 run、612,456 行业务数据，数据与存储验收通过，预测偏差保留，全部 calibrated=false。该批数据仅用于历史链路验证，不是正式全市场数据；详见 [验收记录](../../.agents/brain/NOTES.md#rq-three-model-history-20261022)。本次文档修订不重跑该批次，也不启动全市场采集。

## 范围与已知限制

正式目标为 2024-01-01 起的沪深 A 股历史，包含后来退市的证券；v1、v2、v2trd 独立保存，沿用 sws_2021、daily。北交所、港股、定制模型不在范围内。数据观察时间记录实际取数时间；历史重建名单不等于获得当时可用的数据，所有 run 保持 calibrated=false。

**回补下限固定为 2024-01-01，与本轮 Tushare 行情范围一致**；按交易日执行时首日为 2024-01-02。每只股票按当日上市／退市状态决定是否进入名单，不沿用固定 100 股的最晚上市日作为全市场共同起点。模型在范围内的缺日必须显式登记，不能通过整体推迟起点隐去缺口。批次终点在执行前固定为双方已核验可用的已结束交易日，不因跨午夜自动延长。

如以后要求早于 2024-01-01，先列出从拟议起点到 2023-12-31 的 Tushare 补齐清单及实际缺口，再确认扩围：

| 依赖 | 扩围前必须列出的范围与缺口 |
|---|---|
| 沪深交易日历 | 目标区间开市日及现有覆盖边界 |
| 股票身份与映射 | 该区间曾上市的证券，含后来退市股票、上市／退市边界和历史代码别名 |
| 股票日线及依赖 raw | 按交易日／证券列出 daily、adj_factor、stk_limit、suspend_d 的缺口，区分停牌无行情与采集遗漏；补齐停复牌采集覆盖 |
| 估值／日度基本面 | 若同步支持该区间诊断，列出 daily_basic 及对应目标表缺口，不把只有风险五件套称为诊断数据齐全 |
| 滚动参考历史 | 另列目标首日前 120 交易日等实际所需回看窗口；区分米筐单位检验参考与 Tushare 实现波动参考，不自动假定已有 |

该清单是未来扩围的前置工作，不表示已经核查或授权补抓 2024 年以前的数据。

当前 `RiskOptions.order_book_ids` 是整个区间固定名单，且该名单属于 raw variant 身份。`decode_piece` 要求每份个股数据完整覆盖名单，任意股票缺失会使整日失败。`_instrument_ids` 只将米筐后缀转为当前 canonical 代码查找，尚不能覆盖全市场历史别名。现有链路不能直接改成“今天全市场名单＋历史起点”。

## 建议的数据流程

| 环节 | 建议行为 | 保留证据 |
|---|---|---|
| 名单生成 | 以交易日 D 的上市／退市区间生成沪深 A 股候选，包含当前已退市证券；不按当前名称、ST 状态或当前市值筛历史名单 | 名单生成规则版本、源快照哈希、证券 ID、源代码、上市／退市边界与歧义 |
| 代码解析 | 先解析证券身份，再显式生成米筐请求代码；使用已验证的供应商别名映射，同一证券的旧／新代码去重 | 输入代码、instrument_id、映射来源、有效期已知与否；未知映射单列，不能悄悄丢弃 |
| 逐日采集 | 同一天共享因子收益和协方差；个股载荷、特异收益、特异风险分块采集，保持独立模型身份 | 请求股票集合、实际返回集合、原始响应、实际采集时间、接口错误与配额观察 |
| 覆盖核对 | 按证券核对三份个股数据；仅三份完整且有限的证券进入该日五件套 | 全量候选逐股结果，以及每个接口的返回状态；缺一个接口不能补零或沿用昨天 |
| 整日入库 | 同事务写完整股票的三份个股数据、两份全局数据及覆盖记录 | run_id、因子顺序、名单哈希、覆盖计数、R1/R2、ETL 日期及质量告警 |
| 发布检查 | 结构与数值通过不等于达到正式覆盖要求，覆盖不足只能标为降级 | 发布阈值另行确认；D-022 发布清单完成前不发布正式版本 |

日期边界必须查源定义：上市日是否纳入、退市字段表示最后交易日还是退出日，不能一概用 `D <= delist_date`。边界未确定的证券标为 `universe_boundary_unknown`，对照交易日行情和供应商历史名单核实。SDK `all_instruments(date=D)` 可作为名单对照，但其其他字段未证明都是历史快照，不能当作历史 ST 或行业真源。

本机 rqdatac 3.7.1 的 `ensure_order_book_ids` 会使用内部证券映射转换代码，并可能过滤无效代码。因此要同时保留输入、SDK 可接受代码和实际响应代码；先核实是否在 SDK 层被过滤，再判断供应商是否未返回。不能把客户端过滤造成的缺失登记成正常模型不覆盖。300114.SZ 的验收须覆盖这一请求链路，不能只测数据库别名查询。

## 缺失处理

建议使用以下明确状态，保留原因来源与证据，不把无响应直接叫作“模型正常不覆盖”：

- `included`：三份个股数据完整且通过校验。
- `provider_not_returned`：有效请求完成但供应商未返回；原因尚未确认。
- `partial_bundle`：只返回部分个股接口，保留缺失接口名。
- `invalid_value`：返回了 NaN、Inf、重复证券或非法载荷；质量异常，不能算正常缺失。
- `unmapped_symbol`：无法明确映射证券，不用猜测代码。
- `unsupported_exchange`：已知模型不支持的市场，只记范围差异，不进入沪深分母。

停牌、ST、新上市、退市本身都不自动等同于模型不覆盖。只有供应商规则或真实样本证实原因后，才增加有依据的细分原因。

**部分股票未返回可以形成有覆盖记录的降级日，不再因一只股票缺失使全日失败。** 但认证／配额／网络失败不能伪装成股票缺失；日期和因子轴异常、协方差或因子收益缺失、R2 失败仍整日失败。`invalid_value`、大幅覆盖下降应阻止该批自动继续并供人工检查。每个模型独立记录，不能拿另一个模型补齐。

正式覆盖阈值暂不拍数字：建议先用固定样本之外的一段独立全市场样本，按日记录候选、完整、未返回、异常数量及前日变化，再确认最低覆盖率和异常比例上限。在阈值确认前，只能采集并标记降级，不能自动认定可正式发布。

## 身份、存储与兼容性

- 保留现有固定名单合约；新增动态名单合约版本。新 variant 身份包含模型、行业、期限、单位证据、名单策略和映射规则版本，不包含每天变化的股票列表。每日 manifest 保存实际候选名单及其哈希，不能把名单变化藏在相同观察中。
- 原始响应先完整保存，覆盖评估另存不可变记录；不为凑齐三表而改写 raw。名单或单位更改产生新观察／身份，重跑不得覆盖旧观察。
- 建议新增 `factor.model_run_coverage`，以 `(run_id, instrument_id)` 记录该日候选证券的覆盖状态和各接口状态，关联交易日、源代码、证据；无法映射的源代码在 raw 覆盖记录中保留，入库前须解决或明确登记外部键设计。最终字段、外键和 DDL 另行评审，DDL 仍只放 gr-db。
- 模型、run 和因子顺序继续复用现有 factor.* 表，不按模型建三套表。因子集合变化保留现有独立模型身份规则；跨模型比较先选共同日期、共同完整证券集，并同时展示覆盖差异。
- 覆盖记录与业务数据同日原子提交；失败流水独立提交。`ops.etl_job_run.request` 关联 run、manifest、名单哈希及质量报告，避免靠日志猜测是哪一天。

## 验证 run 与正式读取隔离

本版选定 **D-022 发布清单白名单作为正式读取的唯一入口**。以下是待实施的读取／发布契约，不能据此宣称当前代码已具备隔离能力。

现有固定 100 股 run 的 `model_run.units.variant_id` 和 `units_evidence` 已明确标识其验证用途，具体身份见验收记录。保留这些不可变 run，不补 UPDATE，也不以修改 calibrated 值改变用途。发布校验须明确排除以下验证 variant 及其所属的全部 run：

| 验证数据 | variant_id |
|---|---|
| 原 v1 三天样本 | `9b342891035f90ab97fa9c7cbfb5c9f20c750e3f375a87013532a5ec50c2175c` |
| v1 固定 100 股历史 | `1ca8691394e9926c1926ae3a05b6d411c0bc63e809c5d73bd5fa6cda26b3ab56` |
| v2 固定 100 股历史 | `9157b952b11b53fba6f3bf54f4bc4daa9af952fefdabe07f5f253c3a4cef4290` |
| v2trd 固定 100 股历史 | `17b6adc528b4a896a6156671ebc657c4a296072d11052d537208e881c27fa5ae` |

后续独立全市场样本同样登记为验证用途，不能因股票数量多就自动进入正式清单。用途登记的存储形式随 D-022／导入收据设计评审，不在本文假定已有 `purpose` 字段。`calibrated=false` 表示未校准，**不是验证／正式用途标记**；provider 归属、model_id、因子数或采集时间也不能代替用途判断。

正式读取规则如下，详见 [D-022](../../.agents/brain/DECISIONS.md#d-022)：

1. 先按请求的 `diag.data_version` 取得已发布清单，再取得该版本为指定模型、行业体系和交易日钉住的具体 run_id。区间读取必须逐日钉住，不能只给模型名后查询“最新”。
2. 五张业务表及覆盖表均以同一个 run_id 读取，核对日期、因子顺序和模型身份；取数截止使用版本发布时刻，不能用 `now()`。采集／可用时间不得晚于该发布截止，也不能伪装为历史当时可得。
3. 发布校验拒绝验证用途 run；正式读取不得接收任意 run_id 覆盖清单，不得回退到最大采集时间、同模型其他 run、旧模型或固定 100 股样本。清单缺失、未发布或没有目标日／模型时，相关指标返回 unavailable 并说明缺失依据。
4. D-022 尚未落地或覆盖阈值尚未确认时，不能开放正式风险数据读取。研究比较可以显式选择验证 run，但必须走明确的验证用途，结果保留 run 清单与“验证数据／未发布”标识，不进入正式诊断版本或其缓存。
5. 发布资格与校准状态分别判断。将来允许发布的未校准 run 仍保留 calibrated=false，下游依赖指标标为 degraded；发布不等于自动校准。

## 持仓诊断如何消费降级日

依据 [D-017](../../.agents/brain/DECISIONS.md#d-017)，持仓诊断先取得完整输入持仓及原始权重，再按发布清单选定的 run_id **左连接**覆盖表和个股风险数据。不能从已有 exposure 行反向生成持仓集合，也不能用内连接丢掉没有数据的股票。

| 覆盖情况 | 诊断行为 |
|---|---|
| `included` 且三份个股数据完整 | 使用该 run 的数据；若 run 未校准或该日存在已批准的覆盖降级，保留对应 degraded 原因与覆盖范围 |
| 未返回、部分接口缺失、身份未解析等 | 保留持仓、原始代码、原始权重和来源状态；相关指标返回 `UnavailableMetric`，不带 value，不补 0、不估算、不拿其他日／模型代替 |
| 覆盖表没有这只持仓 | 标为覆盖未知／不可用，不推断为正常不覆盖或零风险；记录覆盖证据缺失 |
| 覆盖状态为 `included`，但明细缺失或日期／run 不一致 | 按完整性异常阻断相关计算并记录错误，不能自动按普通降级日消费 |

覆盖统计同时展示股票数量与原始持仓权重的已覆盖／未覆盖部分，分母保留完整持仓。只要某个组合风险指标依赖的非零持仓存在缺失，该完整组合指标（如总风险及完整风险贡献）就返回 unavailable；不能剔除这些持仓后重新归一化，输出看似完整的组合数值。其他不依赖缺失风险数据的指标可以独立计算。

若另行提供“已覆盖子集分布”，仅可按 D-017 在已知子集内归一化，明确标 degraded、子集范围和原组合覆盖权重，并继续展示未覆盖持仓；不能把它当作全组合风险结果。这不改变缺覆盖持仓本身的不可用状态。

例如 80% 持仓有完整风险数据、20% 无覆盖时，20% 持仓仍出现在报告中，标明相关指标不可用；覆盖权重为 80%，完整组合风险不可用，不用剩余 80% 的结果估算整体。发布层的全市场覆盖率达标，也不能覆盖某个具体组合的这项检查。本文不新增或拍定任何正式覆盖阈值。

## 流量实测与全市场配额估算

依据 2026-10-22～23 固定 100 股、2024-01-02～2026-10-21 共 676 个交易日、三个模型的[实测记录](../../.agents/brain/NOTES.md#rq-three-model-history-20261022)。逐历史日已保存账户采集前后计数和观测时间；计费刷新延迟使许多单日差值为 0，不能解释为零消耗。本次还观察到一次跨午夜重置。

下表使用排除首月并行单位探针、每批前 5 日启动窗口和跨计数重置窗口后的**月内平均账户增量分布**。这是日均消耗估计，不是逐请求精确计费；P95 是这些窗口均值的分位数，不是全市场预测的置信上界。

| 模型 | 每模型日／100 股中位消耗（KiB） | 月内均值 P95（KiB） |
|---|---:|---:|
| v1 | 26.15 | 30.18 |
| v2 | 37.27 | 43.64 |
| v2trd | 41.57 | 50.43 |
| 三模型合计 | 104.99 | 124.25 |

以此前 2026-10-14 的 Tushare 沪深 **5,225 股**作为规模参照（不是每天固定名单），按未四舍五入的实测值计算：

```text
三模型总量 = (v1 + v2 + v2trd 的每模型日消耗) × (5,225 / 100) × 676
           ≈ 3.54～4.19 GiB
可用日配额 = 1 GiB × 90% = 0.9 GiB
配额日数   = ceil(三模型总量 / 可用日配额) ≈ 4～5 天
```

这里已经把三个模型相加，**不能再乘 3**。用户所说“每天 1G”按本次账户返回的 bytes_limit=1,073,741,824 字节（1 GiB）计算，保留 10% 余量；将来运行时仍以账户实际限制和剩余额度为准。如果按十进制 1 GB=1,000,000,000 字节预算，同一估计约需 5 个配额日。

这只是规划用的线性估算，不是完成时间承诺或严格上界。协方差与因子收益不随股票数线性增长；历史在市股票数、分块请求、SDK 证券映射加载、重试、预检及其他任务共享配额都会改变消耗。正式估算应改用每日动态名单大小求和，并由独立全市场样本校正；不能拿“4,000 股一个季度分钟线”的容量参照直接换算日频风险五件套。

待设计与实施获准后，先对三个模型各一个完整的已结束交易日测全市场五件套，记录请求范围、批次数和配额更新窗口，等待计数刷新并隔离其他任务消耗；只有范围、单位与观察可信时才更新预计配额日数。该样本仍属验证数据，不能自动确定正式覆盖阈值或启动全量回补；阈值与后续批次需依据独立样本另行确认。

## 实施顺序与验收

本版复核并取得实施确认后，依次实现：日期名单与别名解析、版本化 raw 身份与覆盖记录、同日事务 writer、D-022 发布隔离与诊断读取；再做独立全市场样本，依据样本另行确认正式覆盖阈值和回补批次。受影响位置为 `config/ricequant_risk.py`、`raw/ricequant/risk_shapes.py`／`riskmodel.py`、`ingest/ricequant/riskmodel.py`、gr-db 新迁移及 gr-api 诊断取数边界；D-022 的具体表结构另行评审。当前不修改这些代码或 DDL。

端到端必须覆盖：上市首日、退市边界、后来退市证券、300114.SZ 历史别名、停牌、单接口缺失、空响应、未知代码、协方差失败、配额中断续跑及重复观察。断言三个个股表使用同一完整集合；所有候选在覆盖表或未映射清单中有去向；失败日无半套业务数据；不同模型不互相补值；available_at 为实际观察时间。

补充验收要求：

- 2024-01-01 下限和首交易日生效；请求更早范围时先生成 Tushare 补齐清单，不静默扩围。
- 验证 run 即使采集时间最新、模型名相同，也不能被正式发布或正式读取；清单缺失时返回不可用，不能回退。测试范围包含原三天样本、三个固定 100 股 variant 及后续全市场探针。
- 同一 data_version 在后续新增 run 后仍读取原清单的 run，五表与覆盖表保持一致；研究用途不能污染正式读取或缓存。
- 80% 覆盖／20% 缺失的持仓用例保留全部输入和权重，未覆盖部分无数值，完整组合风险 unavailable；已有数据的独立指标不受误伤。覆盖记录缺失、included 但缺明细也有独立失败断言。
- 配额估算只计算一次三模型总量，按实际 bytes_limit 和余量预算；计数延迟、跨日重置和并行任务干扰均有明确处理。
