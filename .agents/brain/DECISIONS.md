## 架构与运行边界

<a id="d-001"></a>

### D-001 包独立安装，公共能力保持单向依赖

发行名／目录名采用 `gr-x`，import 采用 `gr_x`。曾经多个发行包共用 `getrich/`，导致安装覆盖与单包不可用，因此不恢复共享命名空间。

`gr-tools` 是无一方依赖的叶子包，承载通用日志、文件和表格工具；领域指标归所属包。共享日志曾让数据包反向依赖回测包，故公共能力不能通过反向 import 复用，依赖边界由静态测试守卫。

<a id="d-002"></a>

### D-002 配置来源统一，领域职责与应用组装分开

环境变量优先于 `.env`，避免本地文件覆盖 CI 或命令行指定的目标；连接、凭证、机器路径和运行开关留在环境层，Python 模型负责类型、默认值和校验，YAML 只存结构化采集参数。workspace 根不能误认成成员包，否则会读错环境文件、改变数据与产物路径。

公共日志模型与输出能力归 `gr-tools`；模块记录事件，进程入口配置输出。各包不维护相互独立的日志框架。

**2026-09-18 已实施**：全量 `gr_data.config.Settings` 会让 PG 命令校验 Web／回测配置，导入还可能创建 `.env`；仅移动文件无法消除耦合。现按应用组装：gr-data 保留数据模型，gr-api 拥有 API／worker 组合，其他 CLI 只加载需要的模型。公共环境加载返回快照，YAML 与类型模型使用同一来源；模型导入不读写环境文件。启动入口和配置迁移说明见 [gr-data 手册](../../packages/gr-data/README.md#配置与日志)。

旧全量单例随仓内调用方迁移移除，不用反向导入 API 的兼容层维持旧结构。不新建 gr-config 包，不将领域组合搬进工具包；API／Celery 绑定自身应用配置，数据库设施接收窄配置。

当前默认 `inproc` 只依赖 PostgreSQL；Redis／ClickHouse 按启用的能力使用。配置里有连接地址不表示服务已启动，也不应成为所有命令的必需依赖。

<a id="d-003"></a>

### D-003 PostgreSQL 是行情与事务真源

早期 PG 与 CH 同存行情导致两套 schema 与冲突口径。行情和事务业务统一存 PostgreSQL／TimescaleDB；ClickHouse 只存因子时序输出，DuckDB 只作临时计算，Redis 只作缓存与协调。

新增持久化能力必须按实体职责选择存储，不能为了某个查询方便再建一套行情真源。

<a id="d-004"></a>

### D-004 部署实例与仓库分离，数据使用 named volume

仓库 `deploy/` 只维护可复现模板，真实环境文件、数据和运维实例位于仓库外。同步的是 deploy 内容，不覆盖部署侧凭证与主机配置；机器调优由部署侧管理。

macOS 文件共享层的 bind 数据目录曾使 PostgreSQL 出现文件／POSIX 语义异常。PG、CH、Redis 数据使用 named volume，配置与日志可以 bind；备份走数据库逻辑导出，不拷运行中的数据目录。此选择牺牲宿主机直接浏览数据文件的便利，换取数据完整性。

2026-10-10 用户确认：PostgreSQL 使用 TimescaleDB 非 `-oss` 镜像（Timescale License），部署、CI 与测试 fixture 同一版本。`-oss` 版缺压缩、保留策略和后台作业；gr-db 的相关 DDL 用 `EXCEPTION` 兜底，迁移会成功但分钟行情不压缩、`realtime.tick_buffer` 不清理，问题不报错。该许可允许自行部署与内部商用，不得把 TimescaleDB 作为托管数据库服务对外提供。同时在本机首次部署、尚无数据时选定 PostgreSQL 18，避免日后为大版本升级做导出／重建；数据目录以数据页校验和与 builtin C.UTF-8 排序规则初始化，这两项初始化后不可更改。

<a id="d-005"></a>

### D-005 Redis 缓存与锁共存时禁止自动淘汰

同实例的缓存、分布式锁与限流计数器不能使用 LRU 等自动淘汰策略，否则锁可能先于业务释放而消失，破坏互斥。使用容量上限与 `noeviction`，缓存靠 TTL 回收，写满显式失败。

若需自动淘汰缓存，先隔离到独立实例；逻辑 DB 不能隔离实例级淘汰策略。当前不启动 Redis 不改变将来启用时的边界。

<a id="d-006"></a>

### D-006 DDL 是存储契约真源，迁移与字典共同校验

全部 DDL 归 `gr-db`。设计稿表达产品意图，不保证与当前库一致；曾因引用列沿用旧 VARCHAR／UUID 假设造成接口失败。引用主键时对齐现行 DDL，选股策略与诊断用户引用亦如此。

迁移以 `file_name + checksum` 记账，内容变化会触发重新应用，因此迁移必须幂等、schema 全限定；不为整理文档修改已记账 SQL。

数据字典从活库 catalog 生成，并与 canonical contracts、注册表、表归属核对，不手写第二份字段真源。受管 schema 以 DDL 为准，包含 `diag`，排除 TimescaleDB 内部 catalog。新增／修改迁移的注释由门禁校验，存量欠账不阻塞无关改动。

## 接口与选股回测

<a id="d-007"></a>

### D-007 前后端共用实际契约与单一请求层

旧前端类型曾掩盖不存在的响应字段、把成交流水误当开平回合；并行接口层又出现漏认证和重复剥响应信封。前端类型与实际后端响应对齐，不能根据设计稿猜字段或聚合语义。

统一请求入口负责认证、401、业务错误与响应信封；领域 API 返回实际 data，视图转换在消费端完成。接口粒度或枚举未知时先确定业务契约，不靠宽泛类型隐藏差异。

<a id="d-008"></a>

### D-008 选股快照与入池日期采用保守历史语义

`pick.batch` 与 `pick.item` 保存上传批次和每日标的池。`strategy_kind` 与业务分类分开，避免选股／择时类型占用分类体系；未回填类型的存量策略不自动进入选股列表。

CLI 导入没有登录用户或管理导入 job，因此 `uploaded_by` 可空，`import_job_id` 保留但不绑定本仓尚未定义的 job 外键。策略引用使用真实主键类型，对外仍使用 `strategy_code`。

`pick` 的交易所码 `SSE/SZSE/BSE` 与 `meta` 的 `XSHG/XSHE/XBSE` 不同；关联标的与日历必须统一转换，否则会静默缺失历史关联。

连续导入优先上一交易日 active 批次；漏传或日历缺失时保留原 `entry_date`，不重置为今天。偏早的日期可解释、可修正，重置会丢失历史。`product_entry_date` 的兜底也是 `entry_date`，保留上传方提供的更早起点。查询优化必须维持漏传、空仓和重新入池的语义。

<a id="d-009"></a>

### D-009 Black-Litterman 保留量纲与观点方向

先验 Π 与观点 Q 分别归一化曾制造数量级差异，使后验压过负观点、产生错误仓位方向。两者保留自然量纲，不做互不一致的归一化。

病态协方差不能把数值噪声当最优权重，退化时回退为按方向等权；验证必须包含非退化数据的后验路径，不能只测相同价格序列触发的 fallback。

仍有两个未决建模口径：当前 Ω 取法使 τ 约掉；Q=score 尚未标定成预期收益。调整它们会改变策略含义，须先确定模型口径，见[待决问题](../../docs/plans/backlog.md)。

## 数据与因子口径

<a id="d-010"></a>

### D-010 因子模型显式保存单位、精度与校准状态

因子模型内风险量可能年化、收益量仍为日频，单一 `annualization_basis` 无法描述两者。下游以 `model_run.units` 为准；不能把日频小数的因子收益按风险年化口径解释。

协方差使用双精度以满足矩阵运算精度；模型保存活跃因子集合校验值。全区间五表自洽校验通过前保留 `calibrated=false`，下游必须暴露未校准状态，不能展示成正常可信结果。

当前 `factor.*` 归属仍是表级。自研与采购模型若要同表并存，必须先设计表 + run_id 的归属隔离，不能直接混写。

2026-09-18 因 DataYes 试用到期，新增米筐标准风险五件套接替实现；切换仍需显式转移全部 8 张 `factor.*` 表归属，不允许两个 provider 并行写入。保留旧 CNE6 历史，米筐按模型、行业体系和实际因子顺序建立独立身份，每次日度观测建立不可变 run；下游必须显式选择模型。米筐源单位从已核对配置读取并换算到现有表契约，特异风险接口为 σ，入库先平方；未完成全区间校准时保持 `calibrated=false`。供应商未提供逐值发布时间，`available_at` 保守采用 raw 实际采集时间，历史回填不能充当当时已知数据。

2026-10-22 迁移 047：风险数组（因子顺序、载荷、协方差、因子收益）不接受空数组、多维、NULL 或非有限元素，由数据库约束拒绝；明细行因子数与所属 run 一致由入库门禁保证。通联载荷此前允许 NaN 入库，其行业哑变量校验也把 NaN 当 0；NaN 是「非该行业」还是真缺失未经真实样本核实，因此不做转换、写库前硬失败。恢复 DataYes 前须先用真实 raw 定口径。

<a id="d-011"></a>

### D-011 因子矩阵按规范顺序对齐，集合按时期校验

历史供应商样本中，暴露、收益和协方差宽表的因子集合相同但顺序不同；照源列序转数组会得到形状合法、经济含义错误的结果。

所有宽表按规范顺序显式 reindex；缺失／重复列拒绝处理。协方差行列标签集合、对称性和对角元需要校验；行业哑变量与 COUNTRY 的约束不能用取最大值兜底掩盖错位。

活跃集合从当期数据派生，按时期核对并记录 hash；不能把跨 SW14／SW21 的全历史并集当作一个模型，也不能将 49／52 固定成所有日期通用的维度。

<a id="d-012"></a>

### D-012 单表单一来源，跨源映射按主键隔离

同一业务表的不同供应商可能采用不同单位、复权和缺失口径，因此同表只允许一个 provider 写入，转移归属必须显式操作。

唯一现有例外是 `meta.symbol_map`：主键包含 `(source, source_symbol)`，不同来源写入互不相交的行，这正是跨源对齐的用途。不能将该例外推广到主键无法按 source 隔离的业务表。

2026-10-22 历史换码补充：迁移 046 移除 `(instrument_id, source)` 反向唯一约束，保留 `(source, source_symbol)` 主键，允许同一证券在一个来源下有多个经证据核实的历史代码。北交所依 Tushare `bse_mapping` 原样落盘对照；中航电测 `300114.SZ → 302132.SZ` 依公司 2025-02-15 实施公告（2025-02-17 生效）登记。原始代码不改写、不为旧代码新建第二个证券，已有映射冲突拒绝。身份别名不代表历史代码有效期或 PIT 可得性。

新旧代码同日重复仅在全部核心数值一致时合并，优先 canonical 观察；不同值硬失败。2024 年以来样本中，中航成飞有 268 个重复交易日，OHLCV、复权及估值一致；每日指标仅 `limit_status` 有 264 天不同，新代码 268 天均符合日线涨跌方向，旧代码固定 0。对此已核实字段显式按新代码保留并记录计数，raw 双份证据不删；不泛化豁免其他证券或字段。

2026-10-22 用户确认显示口径：一只证券一个持续身份，多个代码指向它。一期报告显示当前代码与名称，用户输入旧代码时注明历史别名，不要求显示当时的代码与名称。历史代码／名称有效期与未来换码流程列为后续项，任一条件出现即须先补齐：回测或组合回放要按当时名称状态（如 ST）筛选；旧代码被另一证券重新使用（现有别名登记会硬失败而不是静默错配）。

2026-10-23 触发历史代码有效期的最小实现：米筐动态历史名单需要按交易日选择请求代码，仅有永久身份别名已不足以保证请求正确。用户确认分别处理证券上市区间、代码有效区间与停牌；新增一份带公告证据、带版本的代码区间规则，目前仅含 `300114.SZ → 302132.SZ`（2025-02-17 开市生效，公告 https://static.cninfo.com.cn/finalpage/2025-02-15/1222544408.PDF）。北交所不在本次米筐范围，不建设通用公告核定系统。上市区间默认使用 Tushare 主源日期，先刷新并以真实退市样本核验开闭口径；人工核定仅处理有公告证据的个别源冲突，每条例外留证，超过 5 条须用户确认。规则升级使用新 variant，保留旧规则重放、既有降级 run 与已记账 048，不原位改写历史观察。

<a id="d-013"></a>

### D-013 派生行业分类必须披露覆盖与历史限制

从 datayes CNE6 暴露值派生行业，只是官方三级分类接入前的受限来源：仅覆盖模型内 A 股、只有一级、使用供应商英文行业标识而非申万官方码、区间起点受导入窗口截断。官方代码未知时保持空值，不猜映射。

逐日归属压缩为 `[in_date, out_date)`，结束取下一段起点；同类相邻区间只在间隔不超过 40 自然日时合并。长停牌期间是否重分类未知，不能补造连续历史。跨月分批必须保留区间上下文。

资产类别只映射能够确定的 stock／etf／fund；交易所不足以推断期货等资产类别。缺失应触发 degraded，不能用错误类别制造完整分布。

接入官方层级、成分和生效日期后显式转移表归属；不同来源的分歧可用于质量核验。

<a id="d-014"></a>

### D-014 可用时间优先可信披露时间，禁止报告期兜底

PIT 的 `available_at` 优先使用供应商逐行时间戳，其次公告日，最后才是交易日加文档发布小时；必须保留依据与可信度差异。统一在 `ingest/pit.py` 处理并显式使用 Asia/Shanghai。

报告期 `end_date` 不是信息可得日。以年报报告期兜底会提前看到次年披露的信息，制造前视收益；缺失披露依据不能通过这类兜底消失。

<a id="d-015"></a>

### D-015 可取历史与可一致计算的模型窗口分开

2026-08／09 的历史探针中，本账号 CNE6 五表可取起点为 2021-08-02；供应商 2020-12-31 演示样本不能证明账号拥有同样权限。此证据不是永久 API 保证，权限或来源改变时重验。

历史逐日核对发现 2021-11 五表的 SW14→SW21 切换不同步，因此一致的 `cne6-sw21` 入库窗口从 2021-12-01 起。端点名称带 SW21 也不能保证历史口径一致。

暂不把切换前四个月硬塞到同一个 model_id：现有因子定义的 ordinal 按 model_id 唯一，两套体系会冲突。支持旧体系前先选择独立 model_id 或按版本建模；每个 run 内五表必须逐日一致。

<a id="d-016"></a>

### D-016 批量处理有界，但不能改变时序与事务语义

历史全量导入存在峰值内存与长事务压力。输入按可独立处理的分区分批，验证实际落库与作业结果；不能以没有异常日志代替成功验收。

模型集合逐期核验，行业区间压缩保留跨月上下文；不能把全历史并集当模型，也不能把每个月割裂成新行业区间。批处理超时单独配置，不放宽交互 API 超时。

<a id="d-023"></a>

### D-023 停复牌用事件表承载，缺数不冒充停牌

2026-10-21 确认：Tushare `daily` 停牌期间不返回行，全天停牌日在 `stock_bar_1d` 中不存在；原 `trading_status` 因此只把日内停牌的有成交日标成 HALTED，且未抓 `suspend_timing` 无法区分。改为新建停复牌事件表保存 `suspend_d` 原始事件（含 `suspend_timing`），读取时结合交易日历推导逐日状态：正常交易、全天停牌、日内停牌、未知。交易日既无 bar 也无停牌事件记为未知，不推断为停牌，以免把真实缺数伪装成停牌（PA-12）。

不在 bar 表插入无价格的占位行：会破坏按 OHLC 非空校验的消费方与压缩统计。事件表与 `stock_bar_1d` 中派生列共用同一份 raw，保持单表单一来源。

2026-10-21 已落地 044：`market.stock_suspend_event` 保存 S/R 及源时段，`market.stock_suspend_coverage` 保存成功请求日期、raw 哈希与分区观察时间；合法空响应也记覆盖，旧 raw 没有凭据须重抓。事件按证实日期替换、覆盖写入及已有 bar 的状态刷新同事务提交；较旧观察不能覆盖较新观察。覆盖凭据只证明当前采集，不是 D-022 发布版本或历史 PIT。

状态固定为 `NORMAL`／`HALTED`／`INTRADAY_HALTED`／`UNKNOWN`。无时段 S 且无 bar、无 R 才判全天停牌；有 bar 的日内 S 保留日内停牌状态，同日 R 不抹掉 S；无时段 S/R 同日或其他冲突保留未知，不猜事件先后。读取函数结合上市区间、开市日历逐日推导，缺交易所日历拒绝，不将沪深日历套用于北交所；不据日级状态推断开盘可买性。

<a id="d-024"></a>

### D-024 涨跌停哨兵值写 NULL，用三态列区分不设涨跌幅与未知

2026-10-22 确认：Tushare `stk_limit` 用哨兵值表示当日不设涨跌幅（新股上市初期等），2026-09 样本为北交所 `99999.99/0.0`、沪市 `99999.999/0.01`、深市 `999999.999/0.01`。沪深哨兵为正且上限大于下限，曾通过合法性检查，以 99999.999 这类「涨停价」写入 54 行；回放判断「开盘达到涨停价不买」时会被当真价格使用。

哨兵值改写 NULL，并以迁移 045 新增 `stock_bar_1d.price_limit_status`：`LIMITED`／`NO_LIMIT`／`UNKNOWN`，NULL 为未评估（045 之前或其他供应商写入）。只写 NULL 会让回放分不清「不设涨跌幅、可照常买入」与「未知、执行无法确定」（PA-12），DS05 也要求不按固定比例或上市规则推断，故用显式列表达。数据库约束保证 `LIMITED` 两侧有值、`NO_LIMIT` 两侧为 NULL。

哨兵须两侧同时满足（`up ≥ 99999` 且 `0 ≤ down ≤ 0.01`）；只有一边出现哨兵量级时按非法值记 `UNKNOWN`。`NO_LIMIT` 属正常语义，不计软告警；首日无 `stk_limit` 行记 `UNKNOWN`，不推断为 `NO_LIMIT`。阈值来自单月样本，历史回补须复核更早年份的取值。

<a id="d-025"></a>

### D-025 原油 TAS 价差与期货绝对价格分开解释

2026-10-25 实测 Tushare `SCTAS2510.INE` 与 `SCTASL.INE` 的 2025-09-03 low/close 为 -0.1，而 settle=491.8 与 SC2510 同日结算价相同。依据[能源中心 2023-03-29 通知](https://www.ine.com.cn/eng/circularnews/circular/202303/t20230329_822378.html)，TAS 是按当日结算价及其偏移量成交，2023-04-10 夜盘起申报范围为结算价 ±2 元/桶。供应商 SCTAS 的 OHLC／前收记录价差，结算字段仍为绝对价格；两者不可当作同一价格尺度。

raw 按源义保留有符号价差与 NULL；以明确代码模式及基础信息 `exchange=INE, fut_code=SCTAS` 共同识别，不向普通合约放宽价格规则，不向成交量／金额／持仓量放宽非负及有限性检查。不能取绝对值、填零或静默加结算价制造绝对 OHLC。普通期货目标表目前没有 TAS 价差映射，正式入库及消费前必须另定可区分的语义；在此之前 `FutureBars1dImporter` 按代码形态整行排除 SCTAS 行并计软告警，不把负价差置 NULL、也不把正价差当绝对价写入；此前临时库样本验收只证明既有数值转换与幂等链路，不证明 TAS 绝对价格可用。

## 持仓诊断

<a id="d-017"></a>

### D-017 缺数据显式不可用，不静默估算

`UnavailableMetric` 没有 value 字段，避免不可用结果被构造成数值 0。分布无数据返回 unavailable，不能用空字典表示“已算过但没有行业”。

部分覆盖只在已知子集内归一化，并标记 degraded 和覆盖范围，不把缺失权重当 0 来凑完整分布。依赖未启用模块的检测器也显式返回未触发与 reason_code，避免缺项被理解成“查过，没有问题”。

<a id="d-018"></a>

### D-018 幂等资源、纯计算缓存与展示状态分离

每次新提交创建新 snapshot；只有同一 UUIDv4 Idempotency-Key 重放同一资源，同键异体返回 409。不按相同请求体永久复用快照。

计算缓存只包含规范化的标的、权重等纯计算输入，不包含 plan_id、label、intent、覆盖画像或盲点等请求／展示状态，避免跨用户共享缓存串入展示数据。计算载体变更时更新版本。

A–E 显式区分 ready／unavailable／failed；报告与数值基于同一组固定运行结果。失败方案保留输入与安全错误，新快照重试不改旧终态。零权重校验先于可解析子集过滤，并保留完整输入回显。

<a id="d-021"></a>

### D-021 诊断计算放在 gr-api 内的纯计算模块，组合回放另写

2026-10-21 确认：一期新增的协方差、风险贡献、L3／L4、回放、VaR／CVaR、Beta 等计算放在 gr-api 内的独立模块，只依赖 numpy／polars／gr-tools，不查库、不 import API 与数据接入代码，由静态测试守卫；`services/diagnosis.py` 只负责取数与组装。这样公式可对照手算案例单测并单独人工审核。不新建包，避免为边界多维护一套发行与依赖；需要时再抽出。

组合回放（PA-12）新写，不复用 gr-backtest。逐条对照后，gr-backtest 不支持或做法相反的包括：税前应收分红与派息日到账、小数股、开盘价达到涨停价不买且次日重试、按股票预留现金、退市终止、股票／应收／现金分开记账；它还会带入 pandas、matplotlib 等依赖。只借用日线时区钉法等零件，两处撮合语义不同，不合并。

<a id="d-022"></a>

### D-022 数据版本是发布清单，由 gr-data 发布

2026-10-21 确认：`diag.data_version` 的每个版本是一份发布清单，记录发布时刻与 `available_options`，并逐数据集钉住数据日期与组成版本（导入收据或代际 ID；米筐钉住具体 run_id）。缓存隔离与区间重算的"未被修订"判定比较组成版本，不扫业务表计算内容哈希。诊断取数以版本发布时刻为截止，不用 `now()`，否则同一版本下不同报告会读到不同数据。

版本由 gr-data 在一期所需数据集导入并通过质量检查后，以独立的发布步骤写入，诊断只读；不在 API 启动或多个 worker 中调度发布。表结构以迁移审查为准，与可靠性计划的 B1 收据、B2 代际一起设计。

2026-10-23 用户确认一期轻量限制：诊断仅支持最新日，暂不建立可变数据版本表。发布清单逐项钉住组成收据／风险 run；当前组成收据一旦变化，旧版本标为已被修订、不可复算，需发布新版本，不能回退读取最新数据冒充原版本。发布时刻过滤不具备恢复已被 UPSERT 覆盖数据的能力；历史报告可保留计算产物，但不承诺重算，也不能作为新请求的有效缓存。将来需要历史复算时再升级完整版本表。失效与组成写入需原子衔接，统一读取须在一致性快照内核对当前收据，防止并发修订混读。

同次确认：试行全市场发布门槛为 complete × 1000 ≥ candidate × 999（candidate > 0），身份及上市边界未知为 0；组合层要求全部非零持仓的所需数据完整，缺失按 D-017 不可用。validation 用途永不原地转正，production 使用独立 variant。诊断专用数据库角色延后，一期由数据库约束／触发器拒绝发布明细引用验证 run，保留直接绕过应用 INSERT 被拒绝的验收反例。

实施分为 2a（用途登记、风险整套单一收据、run 绑定、采集／入库双水位）和 2b（发布清单、发布程序、统一读取入口）。两批 DDL 各自先隔离验证再审阅批准工作库执行。2a 完成后允许三个 production 模型自 2024-01-02 回补，前 20 个实际交易日先逐批验证覆盖／流量／告警，达标再继续；2b 完成并发布前正式风险读取仍关闭。2a 不冒充 B2 权威顺序、B3 全量代际发布或完整历史可复算能力。

### D-020 mock 认证默认关闭，无效 JWT 不回退请求头

2026-10-21 确认：`X-User-Id` 请求头任何人都能伪造，原先无论环境都被当作身份，JWT 无效或过期时也回退到它，填上他人或管理员的 UUID 即可读取持仓诊断、通过管理员校验。现改为由 `GETRICH_ALLOW_MOCK_AUTH` 显式开启，默认关闭；只允许 `APP_ENV=dev` 时开启，否则 API 拒绝启动，开启时启动日志打 WARNING。
