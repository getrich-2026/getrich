## 架构与运行边界

<a id="d-001"></a>

### D-001 包独立安装，公共能力保持单向依赖

发行名／目录名采用 `gr-x`，import 采用 `gr_x`。曾经多个发行包共用 `getrich/`，导致安装覆盖与单包不可用，因此不恢复共享命名空间。

`gr-tools` 是无一方依赖的叶子包，承载通用日志、文件和表格工具；领域指标归所属包。共享日志曾让数据包反向依赖回测包，故公共能力不能通过反向 import 复用，依赖边界由静态测试守卫。

<a id="d-002"></a>

### D-002 配置来源统一，领域职责与应用组装分开

环境变量优先于 `.env`，避免本地文件覆盖 CI 或命令行指定的目标；连接、凭证、机器路径和运行开关留在环境层，Python 模型负责类型、默认值和校验，YAML 只存结构化采集参数。workspace 根不能误认成成员包，否则会读错环境文件、改变数据与产物路径。

公共日志模型与输出能力归 `gr-tools`；模块记录事件，进程入口配置输出。各包不维护相互独立的日志框架。

**现行兼容安排**：`gr_data.config.Settings` 仍组装全部配置，这是日志迁移时保留公共 API 的阶段性选择，不表示 Web／worker 配置在业务上属于数据层。不把整个 Settings 搬到工具包，也不增加无法独立安装的仓库根 config 模块。2026-09-18 的按应用拆分建议尚未实施，见[待决问题](../../docs/plans/backlog.md#配置组装入口)。

当前默认 `inproc` 只依赖 PostgreSQL；Redis／ClickHouse 按启用的能力使用。配置里有连接地址不表示服务已启动，也不应成为所有命令的必需依赖。

<a id="d-003"></a>

### D-003 PostgreSQL 是行情与事务真源

早期 PG 与 CH 同存行情导致两套 schema 与冲突口径。行情和事务业务统一存 PostgreSQL／TimescaleDB；ClickHouse 只存因子时序输出，DuckDB 只作临时计算，Redis 只作缓存与协调。

新增持久化能力必须按实体职责选择存储，不能为了某个查询方便再建一套行情真源。

<a id="d-004"></a>

### D-004 部署实例与仓库分离，数据使用 named volume

仓库 `deploy/` 只维护可复现模板，真实环境文件、数据和运维实例位于仓库外。同步的是 deploy 内容，不覆盖部署侧凭证与主机配置；机器调优由部署侧管理。

macOS 文件共享层的 bind 数据目录曾使 PostgreSQL 出现文件／POSIX 语义异常。PG、CH、Redis 数据使用 named volume，配置与日志可以 bind；备份走数据库逻辑导出，不拷运行中的数据目录。此选择牺牲宿主机直接浏览数据文件的便利，换取数据完整性。

<a id="d-005"></a>

### D-005 Redis 缓存与锁共存时禁止自动淘汰

同实例的缓存、分布式锁与限流计数器不能使用 LRU 等自动淘汰策略，否则锁可能先于业务释放而消失，破坏互斥。使用容量上限与 `noeviction`，缓存靠 TTL 回收，写满显式失败。

若需自动淘汰缓存，先隔离到独立实例；逻辑 DB 不能隔离实例级淘汰策略。当前不启动 Redis 不改变将来启用时的边界。

<a id="d-006"></a>

### D-006 DDL 是存储契约真源，迁移与字典共同校验

全部 DDL 归 `gr-db`。设计稿表达产品意图，不保证与当前库一致；曾因引用列沿用旧 VARCHAR／UUID 假设造成接口失败。引用主键时对齐现行 DDL，选股策略与诊断用户引用亦如此。

迁移以 `file_name + checksum` 记账，内容变化会触发重新应用，因此迁移必须幂等、schema 全限定；不为整理文档修改已记账 SQL。

数据字典从活库 catalog 生成，并与 canonical contracts、注册表、表归属核对，不手写第二份字段真源。受管 schema 以 DDL 为准，包含 `diag`，排除 TimescaleDB 内部 catalog。新增／修改迁移的注释由门禁校验，存量欠账不阻塞无关改动。

## 接口与选股回测

<a id="d-007"></a>

### D-007 前后端共用实际契约与单一请求层

旧前端类型曾掩盖不存在的响应字段、把成交流水误当开平回合；并行接口层又出现漏认证和重复剥响应信封。前端类型与实际后端响应对齐，不能根据设计稿猜字段或聚合语义。

统一请求入口负责认证、401、业务错误与响应信封；领域 API 返回实际 data，视图转换在消费端完成。接口粒度或枚举未知时先确定业务契约，不靠宽泛类型隐藏差异。

<a id="d-008"></a>

### D-008 选股快照与入池日期采用保守历史语义

`pick.batch` 与 `pick.item` 保存上传批次和每日标的池。`strategy_kind` 与业务分类分开，避免选股／择时类型占用分类体系；未回填类型的存量策略不自动进入选股列表。

CLI 导入没有登录用户或管理导入 job，因此 `uploaded_by` 可空，`import_job_id` 保留但不绑定本仓尚未定义的 job 外键。策略引用使用真实主键类型，对外仍使用 `strategy_code`。

`pick` 的交易所码 `SSE/SZSE/BSE` 与 `meta` 的 `XSHG/XSHE/XBSE` 不同；关联标的与日历必须统一转换，否则会静默缺失历史关联。

连续导入优先上一交易日 active 批次；漏传或日历缺失时保留原 `entry_date`，不重置为今天。偏早的日期可解释、可修正，重置会丢失历史。`product_entry_date` 的兜底也是 `entry_date`，保留上传方提供的更早起点。查询优化必须维持漏传、空仓和重新入池的语义。

<a id="d-009"></a>

### D-009 Black-Litterman 保留量纲与观点方向

先验 Π 与观点 Q 分别归一化曾制造数量级差异，使后验压过负观点、产生错误仓位方向。两者保留自然量纲，不做互不一致的归一化。

病态协方差不能把数值噪声当最优权重，退化时回退为按方向等权；验证必须包含非退化数据的后验路径，不能只测相同价格序列触发的 fallback。

仍有两个未决建模口径：当前 Ω 取法使 τ 约掉；Q=score 尚未标定成预期收益。调整它们会改变策略含义，须先确定模型口径，见[待决问题](../../docs/plans/backlog.md)。

## 数据与因子口径

<a id="d-010"></a>

### D-010 因子模型显式保存单位、精度与校准状态

因子模型内风险量可能年化、收益量仍为日频，单一 `annualization_basis` 无法描述两者。下游以 `model_run.units` 为准；不能把日频小数的因子收益按风险年化口径解释。

协方差使用双精度以满足矩阵运算精度；模型保存活跃因子集合校验值。全区间五表自洽校验通过前保留 `calibrated=false`，下游必须暴露未校准状态，不能展示成正常可信结果。

当前 `factor.*` 归属仍是表级。自研与采购模型若要同表并存，必须先设计表 + run_id 的归属隔离，不能直接混写。

<a id="d-011"></a>

### D-011 因子矩阵按规范顺序对齐，集合按时期校验

历史供应商样本中，暴露、收益和协方差宽表的因子集合相同但顺序不同；照源列序转数组会得到形状合法、经济含义错误的结果。

所有宽表按规范顺序显式 reindex；缺失／重复列拒绝处理。协方差行列标签集合、对称性和对角元需要校验；行业哑变量与 COUNTRY 的约束不能用取最大值兜底掩盖错位。

活跃集合从当期数据派生，按时期核对并记录 hash；不能把跨 SW14／SW21 的全历史并集当作一个模型，也不能将 49／52 固定成所有日期通用的维度。

<a id="d-012"></a>

### D-012 单表单一来源，跨源映射按主键隔离

同一业务表的不同供应商可能采用不同单位、复权和缺失口径，因此同表只允许一个 provider 写入，转移归属必须显式操作。

唯一现有例外是 `meta.symbol_map`：主键包含 `(source, source_symbol)`，不同来源写入互不相交的行，这正是跨源对齐的用途。不能将该例外推广到主键无法按 source 隔离的业务表。

<a id="d-013"></a>

### D-013 派生行业分类必须披露覆盖与历史限制

从 datayes CNE6 暴露值派生行业，只是官方三级分类接入前的受限来源：仅覆盖模型内 A 股、只有一级、使用供应商英文行业标识而非申万官方码、区间起点受导入窗口截断。官方代码未知时保持空值，不猜映射。

逐日归属压缩为 `[in_date, out_date)`，结束取下一段起点；同类相邻区间只在间隔不超过 40 自然日时合并。长停牌期间是否重分类未知，不能补造连续历史。跨月分批必须保留区间上下文。

资产类别只映射能够确定的 stock／etf／fund；交易所不足以推断期货等资产类别。缺失应触发 degraded，不能用错误类别制造完整分布。

接入官方层级、成分和生效日期后显式转移表归属；不同来源的分歧可用于质量核验。

<a id="d-014"></a>

### D-014 可用时间优先可信披露时间，禁止报告期兜底

PIT 的 `available_at` 优先使用供应商逐行时间戳，其次公告日，最后才是交易日加文档发布小时；必须保留依据与可信度差异。统一在 `ingest/pit.py` 处理并显式使用 Asia/Shanghai。

报告期 `end_date` 不是信息可得日。以年报报告期兜底会提前看到次年披露的信息，制造前视收益；缺失披露依据不能通过这类兜底消失。

<a id="d-015"></a>

### D-015 可取历史与可一致计算的模型窗口分开

2026-08／09 的历史探针中，本账号 CNE6 五表可取起点为 2021-08-02；供应商 2020-12-31 演示样本不能证明账号拥有同样权限。此证据不是永久 API 保证，权限或来源改变时重验。

历史逐日核对发现 2021-11 五表的 SW14→SW21 切换不同步，因此一致的 `cne6-sw21` 入库窗口从 2021-12-01 起。端点名称带 SW21 也不能保证历史口径一致。

暂不把切换前四个月硬塞到同一个 model_id：现有因子定义的 ordinal 按 model_id 唯一，两套体系会冲突。支持旧体系前先选择独立 model_id 或按版本建模；每个 run 内五表必须逐日一致。

<a id="d-016"></a>

### D-016 批量处理有界，但不能改变时序与事务语义

历史全量导入存在峰值内存与长事务压力。输入按可独立处理的分区分批，验证实际落库与作业结果；不能以没有异常日志代替成功验收。

模型集合逐期核验，行业区间压缩保留跨月上下文；不能把全历史并集当模型，也不能把每个月割裂成新行业区间。批处理超时单独配置，不放宽交互 API 超时。

## 持仓诊断

<a id="d-017"></a>

### D-017 缺数据显式不可用，不静默估算

`UnavailableMetric` 没有 value 字段，避免不可用结果被构造成数值 0。分布无数据返回 unavailable，不能用空字典表示“已算过但没有行业”。

部分覆盖只在已知子集内归一化，并标记 degraded 和覆盖范围，不把缺失权重当 0 来凑完整分布。依赖未启用模块的检测器也显式返回未触发与 reason_code，避免缺项被理解成“查过，没有问题”。

<a id="d-018"></a>

### D-018 幂等资源、纯计算缓存与展示状态分离

每次新提交创建新 snapshot；只有同一 UUIDv4 Idempotency-Key 重放同一资源，同键异体返回 409。不按相同请求体永久复用快照。

计算缓存只包含规范化的标的、权重等纯计算输入，不包含 plan_id、label、intent、覆盖画像或盲点等请求／展示状态，避免跨用户共享缓存串入展示数据。计算载体变更时更新版本。

A–E 显式区分 ready／unavailable／failed；报告与数值基于同一组固定运行结果。失败方案保留输入与安全错误，新快照重试不改旧终态。零权重校验先于可解析子集过滤，并保留完整输入回显。
