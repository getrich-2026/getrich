## 架构与运行边界

<a id="d-001"></a>

### D-001 包独立安装，公共能力保持单向依赖

曾经多个发行包共用 `getrich/` 命名空间，导致互相覆盖、单包装不起来，因此采用 `gr-x`／`gr_x` 一一对应，不恢复共享命名空间。

共享日志曾让数据包反向依赖回测包。公共能力因此集中到无一方依赖的叶子包 `gr-tools`，领域指标归所属包；不能通过反向 import 复用，边界由静态测试守卫。

<a id="d-002"></a>

### D-002 配置来源统一，领域职责与应用组装分开

环境变量优先于 `.env`，避免本地文件覆盖 CI 或命令行指定的目标；workspace 根不能误认成成员包，否则会读错环境文件、改变数据与产物路径。

旧的全量 `gr_data.config.Settings` 让 PG 命令也要校验 Web／回测配置，导入时还可能创建 `.env`；只搬文件无法消除这种耦合。2026-09-18 改为按应用组装：gr-data 保留数据模型，gr-api 组装 API／worker，其他 CLI 只加载所需模型；公共环境快照与日志归 gr-tools。不新建 gr-config 包，不用反向导入 API 的兼容层维持旧单例。具体规则见 AGENTS.md §4.5。

<a id="d-003"></a>

### D-003 PostgreSQL 是行情与事务真源

早期 PG 与 CH 同存行情，形成两套 schema 与冲突口径。行情和事务统一存 PostgreSQL／TimescaleDB；各库职责见 AGENTS.md §2。新增持久化能力按实体职责选存储，不能为了某个查询方便再建一套行情真源。

<a id="d-004"></a>

### D-004 部署实例与仓库分离，数据使用 named volume

仓库 `deploy/` 只维护可复现模板，真实环境文件、数据和运维实例位于仓库外；同步模板时不覆盖部署侧凭证与主机配置。

macOS 文件共享层的 bind 数据目录曾使 PostgreSQL 出现文件／POSIX 语义异常。PG、CH、Redis 数据使用 named volume，配置与日志可以 bind；备份走数据库逻辑导出。这牺牲了在宿主机直接浏览数据文件的便利，换取数据完整性。

2026-10-10 用户确认使用 TimescaleDB 非 `-oss` 镜像，部署、CI 与测试 fixture 同版本。`-oss` 缺压缩、保留策略和后台作业，相关 DDL 的 `EXCEPTION` 兜底会让迁移成功却静默不压缩、不清理。该许可允许自行部署与内部商用，不得把 TimescaleDB 作为托管数据库服务对外提供。同时选定 PostgreSQL 18，避免日后为大版本升级导出重建；数据目录以数据页校验和与 builtin C.UTF-8 排序规则初始化，两者初始化后不可更改。

<a id="d-005"></a>

### D-005 Redis 缓存与锁共存时禁止自动淘汰

同实例的缓存、分布式锁与限流计数器不能用 LRU 等自动淘汰，否则锁可能先于业务释放而消失，破坏互斥。使用容量上限与 `noeviction`，缓存靠 TTL 回收，写满显式失败。需要自动淘汰的缓存先隔离到独立实例；逻辑 DB 不能隔离实例级淘汰策略。

<a id="d-006"></a>

### D-006 DDL 是存储契约真源，迁移与字典共同校验

全部 DDL 归 `gr-db`。设计稿表达产品意图，不保证与当前库一致；曾因引用列沿用旧 VARCHAR／UUID 假设造成接口失败，引用主键时须对齐现行 DDL。

迁移以 `file_name + checksum` 记账，内容变化会触发重新应用，因此迁移必须幂等、schema 全限定，不为整理文档修改已记账 SQL。

数据字典从活库 catalog 生成，并与 canonical contracts、注册表、表归属核对，不手写第二份字段真源；受管 schema 以 DDL 为准，包含 `diag`，排除 TimescaleDB 内部 catalog。新增／修改迁移的注释由门禁校验，存量欠账不阻塞无关改动。

## 接口与选股回测

<a id="d-007"></a>

### D-007 前后端共用实际契约与单一请求层

旧前端类型曾掩盖不存在的响应字段、把成交流水误当开平回合；并行接口层又出现漏认证和重复剥响应信封。前端类型照实际后端响应写，不根据设计稿猜字段或聚合语义；统一请求入口负责认证、401、业务错误与信封，视图转换在消费端完成。接口粒度或枚举未知时先定业务契约，不靠宽泛类型隐藏差异。

<a id="d-008"></a>

### D-008 选股快照与入池日期采用保守历史语义

`pick.batch` 与 `pick.item` 保存上传批次和每日标的池。`strategy_kind` 与业务分类分开，未回填类型的存量策略不自动进入选股列表。CLI 导入没有登录用户或管理导入 job，因此 `uploaded_by` 可空，`import_job_id` 暂不绑定外键。策略引用使用真实主键类型，对外仍用 `strategy_code`。

`pick` 的交易所码 `SSE/SZSE/BSE` 与 `meta` 的 `XSHG/XSHE/XBSE` 不同；关联标的与日历必须统一转换，否则会静默缺失历史关联。

连续导入优先沿用上一交易日 active 批次的 `entry_date`；漏传或日历缺失时保留原值，不重置为今天。偏早的日期可解释、可修正，重置会丢失历史；`product_entry_date` 同理兜底为 `entry_date`。查询优化必须维持漏传、空仓和重新入池的语义。

<a id="d-009"></a>

### D-009 Black-Litterman 保留量纲与观点方向

先验 Π 与观点 Q 分别归一化曾制造数量级差异，使后验压过负观点、产生错误仓位方向。两者保留自然量纲。病态协方差退化时回退为按方向等权；验证必须覆盖非退化数据的后验路径，不能只测相同价格序列触发的 fallback。

未决口径：当前 Ω 取法使 τ 约掉；Q=score 尚未标定成预期收益。调整会改变策略含义，见[待决问题](../../docs/plans/backlog.md)。

## 数据与因子口径

<a id="d-010"></a>

### D-010 因子模型显式保存单位、精度与校准状态

风险量可能年化、收益量仍为日频，单一 `annualization_basis` 无法描述两者；下游以 `model_run.units` 为准。协方差用双精度；全区间五表自洽校验通过前保持 `calibrated=false`，下游必须暴露未校准状态。

`factor.*` 归属是表级。2026-09-18 起米筐接替通联，归属已显式转移给 ricequant，不允许两个 provider 并行写入；自研与采购模型若要同表并存，须先设计表 + run_id 的归属隔离。旧 CNE6 历史保留，米筐按模型、行业体系和实际因子顺序建立独立身份，下游必须显式选择模型；每次日度观测是不可变 run，源单位按已核对配置换算（特异风险接口返回 σ，入库先平方）。供应商未给逐值发布时间，`available_at` 保守取 raw 实际采集时间，历史回填不能充当当时已知数据。

迁移 047 起，风险数组不接受空、多维、NULL 或非有限元素。通联载荷曾允许 NaN 入库，NaN 是「非该行业」还是真缺失未经真实样本核实，因此写库前硬失败；恢复通联前须先用真实 raw 定口径。

<a id="d-011"></a>

### D-011 因子矩阵按规范顺序对齐，集合与批次按时期校验

历史样本中，暴露、收益和协方差宽表的因子集合相同但顺序不同；照源列序转数组会得到形状合法、经济含义错误的结果。所有宽表按规范顺序显式 reindex，缺失／重复列拒绝；协方差校验行列标签、对称性和对角元，行业哑变量与 COUNTRY 约束不能用取最大值兜底。

活跃因子集合从当期数据派生并记录 hash，不能把跨 SW14／SW21 的全历史并集当一个模型，也不能把维度固定成所有日期通用。

（原 D-016）历史全量导入有峰值内存与长事务压力，输入按可独立处理的分区分批，但分批不能改变时序与事务语义：模型集合逐期核验，区间压缩保留跨分区上下文；以实际落库与作业结果验收，不以没有异常日志代替成功。批处理超时单独配置，不放宽交互 API 超时。

<a id="d-012"></a>

### D-012 单表单一来源，跨源映射按主键隔离

不同供应商的单位、复权和缺失口径可能不同，因此同表只允许一个 provider 写入，转移归属必须显式操作。唯一例外是 `meta.symbol_map`：主键含 `(source, source_symbol)`，各来源写入互不相交的行；不能推广到主键无法按 source 隔离的表。

历史换码（2026-10-22，迁移 046）：同一证券在一个来源下可有多个经证据核实的历史代码，原始代码不改写、不为旧代码新建第二个证券，冲突映射拒绝。身份别名不代表代码有效期或 PIT 可得性。新旧代码同日重复仅在核心数值一致时合并，不同值硬失败；已逐字段核实的差异（如中航成飞的 `limit_status`）显式按新代码保留并计数，不泛化豁免。

显示口径（用户确认）：一只证券一个持续身份，多个代码指向它；一期显示当前代码与名称，输入旧代码时注明历史别名。

代码有效期（2026-10-23）：米筐动态名单要按交易日选择请求代码，仅有永久别名不够。证券上市区间、代码有效区间与停牌分开处理；带公告证据、带版本的代码区间规则目前只含 `300114.SZ → 302132.SZ`（2025-02-17 生效，[公司公告](https://static.cninfo.com.cn/finalpage/2025-02-15/1222544408.PDF)）；北交所旧码依 Tushare `bse_mapping` 登记，不建设通用公告核定系统。上市区间默认取 Tushare，人工核定只处理有公告证据的个别冲突，超过 5 条须用户确认。规则升级使用新 variant，不原位改写历史观察。旧代码被另一证券重新使用、或回测需要按当时名称状态（如 ST）筛选时，须先补齐通用的名称与代码有效期。

<a id="d-013"></a>

### D-013 通联 CNE6 是受限来源：派生行业与可用窗口

（含原 D-015）通联现为第二档备用源，恢复使用前必须知道以下限制。

**派生行业**：从 CNE6 暴露值派生行业只是官方分类接入前的受限来源：仅覆盖模型内 A 股、只有一级、使用供应商英文行业标识而非申万官方码、起点受导入窗口截断。官方代码未知时保持空值，不猜映射。逐日归属压缩为 `[in_date, out_date)`，同类相邻区间仅在间隔不超过 40 自然日时合并；长停牌期间是否重分类未知，不补造连续历史。资产类别只映射能确定的 stock／etf／fund，缺失触发 degraded，不用错误类别凑完整分布。接入官方层级、成分和生效日期后显式转移表归属。

**可用窗口**：2026-08／09 探针中，本账号 CNE6 五表可取起点为 2021-08-02，演示样本不能证明账号有同样权限；权限或来源改变时重验。2021-11 五表的 SW14→SW21 切换不同步，一致的 `cne6-sw21` 窗口从 2021-12-01 起；端点名带 SW21 不能保证历史口径一致。切换前四个月不硬塞进同一 model_id（ordinal 按 model_id 唯一会冲突），支持旧体系前先选独立 model_id 或按版本建模。

<a id="d-014"></a>

### D-014 可用时间优先可信披露时间，禁止报告期兜底

PIT 的 `available_at` 优先使用供应商逐行时间戳，其次公告日，最后才是交易日加文档发布小时，并保留依据与可信度差异；统一在 `ingest/pit.py` 处理，显式使用 Asia/Shanghai。报告期 `end_date` 不是信息可得日，以它兜底会提前看到次年披露的信息，制造前视收益。

<a id="d-023"></a>

### D-023 停复牌用事件表承载，缺数不冒充停牌

Tushare `daily` 停牌期间不返回行，全天停牌日在 `stock_bar_1d` 中不存在；原 `trading_status` 只能把日内停牌的有成交日标成 HALTED。2026-10-21 改为迁移 044：`market.stock_suspend_event` 保存 `suspend_d` 原始事件（含 `suspend_timing`），`market.stock_suspend_coverage` 保存成功请求日期与 raw 证据，合法空响应也记覆盖；读取时结合交易日历逐日推导状态。交易日既无 bar 也无停牌事件记为未知，不推断为停牌，以免把真实缺数伪装成停牌（PA-12）。

不在 bar 表插入无价格的占位行，那会破坏按 OHLC 非空校验的消费方与压缩统计。事件替换、覆盖写入与 bar 状态刷新同事务提交，较旧观察不能覆盖较新观察；覆盖凭据只证明当前采集，不是 D-022 发布版本或历史 PIT。

状态为 `NORMAL`／`HALTED`／`INTRADAY_HALTED`／`UNKNOWN`：无时段 S 且无 bar、无 R 才判全天停牌；有 bar 的日内 S 保留日内停牌；无时段 S/R 同日等冲突保留未知，不猜先后。缺交易所日历拒绝，不将沪深日历套用于北交所；不据日级状态推断开盘可买性。

<a id="d-024"></a>

### D-024 涨跌停哨兵值写 NULL，用三态列区分不设涨跌幅与未知

Tushare `stk_limit` 用哨兵值表示当日不设涨跌幅（新股上市初期等），2026-09 样本为北交所 `99999.99/0.0`、沪市 `99999.999/0.01`、深市 `999999.999/0.01`。沪深哨兵曾通过合法性检查，以“涨停价”写入；回放判断「开盘达到涨停价不买」时会被当真价格使用。

哨兵改写 NULL，并以迁移 045 新增 `stock_bar_1d.price_limit_status`（`LIMITED`／`NO_LIMIT`／`UNKNOWN`，NULL 为未评估）。只写 NULL 会让回放分不清「不设涨跌幅、可照常买入」与「未知、无法确定执行」（PA-12）；数据库约束保证 `LIMITED` 两侧有值、`NO_LIMIT` 两侧为 NULL。

哨兵须两侧同时满足（`up ≥ 99999` 且 `0 ≤ down ≤ 0.01`），只有一边出现时记 `UNKNOWN`；首日无 `stk_limit` 行记 `UNKNOWN`。`NO_LIMIT` 不计软告警。阈值来自单月样本，回补更早年份须复核。

<a id="d-025"></a>

### D-025 原油 TAS 价差与期货绝对价格分开解释

Tushare `SCTAS*.INE` 的 OHLC／前收记录的是相对结算价的偏移量（2025-09-03 low/close 为 -0.1，settle 为 491.8），结算字段仍是绝对价格。依据[能源中心 2023-03-29 通知](https://www.ine.com.cn/eng/circularnews/circular/202303/t20230329_822378.html)，TAS 按当日结算价及其偏移量成交，申报范围为结算价 ±2 元/桶。

raw 按源义保留有符号价差与 NULL，以代码模式加 `exchange=INE, fut_code=SCTAS` 共同识别；不向普通合约放宽价格规则，不向量／额／持仓放宽非负与有限性检查。不能取绝对值、填零或静默加结算价制造绝对 OHLC。普通期货表没有 TAS 价差映射，在另定语义之前 `FutureBars1dImporter` 整行排除 SCTAS 行并计软告警。

<a id="d-026"></a>

### D-026 期权当前参数不冒充历史参数，ETF 身份不等于权益类别

Tushare `opt_basic` 的行权价和乘数是调整后的当前值（[官方说明](https://tushare.pro/document/2?doc_id=158)），没有历史生效区间。raw 保存不可变观察及哈希；`meta.option_contracts` 的机械映射只供隔离验证。正式参数和行情写入默认拒绝，直至历史参数／发布资格契约单独验收；验证开关只在环境层且默认关闭，开启时也标为未发布，不得开放历史收益、IV／Greeks 或交易消费。报价不乘合约乘数，成交量和 OI 保持手数，金额万元转元；`opt_multiplier` 与 `per_unit` 不混用。

ETF 用 `etf_basic` 的 L／D／P 名单识别；P 是待上市，接口未给退市日期则留未知。非 ETF 的 fund_daily／fund_adj 记录保留 raw，不写 ETF 行情表。分类暂沿用旧规则（一律 equity／cn_a，已知不准确）以免新旧行为分裂；目标口径改用 `fund_basic.fund_type` 单一来源并显式维护映射，未映射或混合型保持未分类，存量错误按“删除后按上市日重写”更正。该任务尚未实施，工作库删除需单独授权。

## 持仓诊断

<a id="d-017"></a>

### D-017 缺数据显式不可用，不静默估算

`UnavailableMetric` 没有 value 字段，避免不可用结果被构造成 0；分布无数据返回 unavailable，不用空字典表示“已算过但没有行业”。部分覆盖只在已知子集内归一化，并标记 degraded 和覆盖范围，不把缺失权重当 0。依赖未启用模块的检测器显式返回未触发与 reason_code，避免缺项被理解成“查过，没有问题”。

<a id="d-018"></a>

### D-018 幂等资源、纯计算缓存与展示状态分离

每次新提交创建新 snapshot；只有同一 UUIDv4 Idempotency-Key 重放同一资源，同键异体返回 409，不按相同请求体永久复用快照。

计算缓存只含规范化的标的、权重等纯计算输入，不含 plan_id、label、intent、覆盖画像或盲点等展示状态，避免跨用户共享缓存串入展示数据；计算载体变更时更新版本。

A–E 显式区分 ready／unavailable／failed，报告与数值基于同一组固定运行结果。失败方案保留输入与安全错误，新快照重试不改旧终态；零权重校验先于可解析子集过滤，并保留完整输入回显。

<a id="d-021"></a>

### D-021 诊断计算放在 gr-api 内的纯计算模块，组合回放另写

2026-10-21 确认：一期的协方差、风险贡献、L3／L4、回放、VaR／CVaR、Beta 等计算放在 gr-api 内的独立模块，只依赖 numpy／polars／gr-tools，不查库、不 import API 与数据接入代码，由静态测试守卫；`services/diagnosis.py` 只负责取数与组装。公式因此可对照手算案例单测。暂不新建包，需要时再抽出。

组合回放（PA-12）新写，不复用 gr-backtest：后者在分红到账、小数股、涨停不买次日重试、现金预留、退市终止和分开记账等撮合语义上不支持或做法相反，还会带入 pandas、matplotlib 等依赖。只借用日线时区钉法等零件。

<a id="d-022"></a>

### D-022 数据版本是发布清单，由 gr-data 发布

`diag.data_version` 的每个版本是一份发布清单：记录发布时刻与 `available_options`，逐数据集钉住数据日期与组成版本（导入收据或代际 ID；米筐钉住具体 run_id）。缓存隔离与重算的“未被修订”判定比较组成版本，不扫业务表算内容哈希；诊断取数以发布时刻为截止，不用 `now()`，否则同一版本下不同报告会读到不同数据。版本由 gr-data 在数据导入并通过质量检查后以独立步骤发布，诊断只读，不在 API 启动或 worker 中调度。

一期轻量限制（2026-10-23 用户确认）：只诊断最新日，暂不建可变数据版本表。组成收据一旦变化，旧版本标为已修订、不可复算，需发布新版本，不能回退读取最新数据冒充原版本；按发布时刻过滤无法恢复已被 UPSERT 覆盖的数据，所以历史报告保留计算产物但不承诺重算。诊断专用数据库角色延后。失效与组成写入须原子衔接，统一读取在一致性快照内核对当前收据。

发布门槛：complete × 1000 ≥ candidate × 999（candidate > 0），身份及上市边界未知为 0；组合层要求全部非零持仓的所需数据完整，缺失按 D-017 不可用。validation 用途永不原地转正，production 使用独立 variant；数据库约束／触发器拒绝发布明细引用 validation run。

实施分两批：2a（用途登记、风险整套单一收据、run 绑定、采集／入库双水位，迁移 049）已落地，三个 production 模型据此回补至 2026-10-21；2b（发布清单、发布程序、统一读取入口）待评审，完成并发布前正式风险读取关闭。2a 不冒充 B2 权威顺序、B3 全量代际发布或历史可复算能力。

## 安全边界

<a id="d-020"></a>

### D-020 mock 认证默认关闭，无效 JWT 不回退请求头

`X-User-Id` 请求头任何人都能伪造，原先无论环境都被当作身份，JWT 无效或过期时也回退到它，填上他人或管理员的 UUID 即可读取持仓诊断、通过管理员校验。2026-10-21 改为由 `GETRICH_ALLOW_MOCK_AUTH` 显式开启、默认关闭，只允许 `APP_ENV=dev`，否则 API 拒绝启动；开启时启动日志打 WARNING。

带了 Bearer token 但验证失败一律 401，可选登录的接口也不降级为匿名或请求头身份。不单靠 `APP_ENV` 门控，因为它默认 `dev`，部署漏配时仍会放行。JWT 默认密钥的启动检查是同类问题，另行处理。
