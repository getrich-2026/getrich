## 架构与运行边界

<a id="d-001"></a>

### D-001 包独立安装，公共能力保持单向依赖

曾经多个发行包共用 `getrich/` 命名空间，导致互相覆盖、单包装不起来，因此采用 `gr-x`／`gr_x` 一一对应，不恢复共享命名空间。

共享日志曾让数据包反向依赖回测包。公共能力因此集中到无一方依赖的叶子包 `gr-tools`，领域指标归所属包；不能通过反向 import 复用，边界由静态测试守卫。

<a id="d-002"></a>

### D-002 配置来源统一，领域职责与应用组装分开

环境变量优先于 `.env`，避免本地文件覆盖 CI 或命令行指定的目标；workspace 根不能误认成成员包，否则会读错环境文件、改变数据与产物路径。

旧的全量 `gr_data.config.Settings` 让 PG 命令也要校验 Web／回测配置，导入时还可能创建 `.env`；只搬文件无法消除这种耦合。2026-09-18 改为按应用组装：gr-data 保留数据模型，gr-api 组装 API／worker，其他 CLI 只加载所需模型；公共环境快照与日志归 gr-tools。不新建 gr-config 包，不用反向导入 API 的兼容层维持旧单例。具体规则见 AGENTS.md §4.5。

<a id="d-003"></a>

### D-003 PostgreSQL 是行情与事务真源

早期 PG 与 CH 同存行情，形成两套 schema 与冲突口径。行情和事务统一存 PostgreSQL／TimescaleDB；各库职责见 AGENTS.md §2。新增持久化能力按实体职责选存储，不能为了某个查询方便再建一套行情真源。

<a id="d-004"></a>

### D-004 部署实例与仓库分离，数据使用 named volume

仓库 `deploy/` 只维护可复现模板，真实环境文件、数据和运维实例位于仓库外；同步模板时不覆盖部署侧凭证与主机配置。

macOS 文件共享层的 bind 数据目录曾使 PostgreSQL 出现文件／POSIX 语义异常。PG、CH、Redis 数据使用 named volume，配置与日志可以 bind；备份走数据库逻辑导出。这牺牲了在宿主机直接浏览数据文件的便利，换取数据完整性。

2026-10-10 用户确认使用 TimescaleDB 非 `-oss` 镜像，部署、CI 与测试 fixture 同版本。`-oss` 缺压缩、保留策略和后台作业，相关 DDL 的 `EXCEPTION` 兜底会让迁移成功却静默不压缩、不清理。该许可允许自行部署与内部商用，不得把 TimescaleDB 作为托管数据库服务对外提供。同时选定 PostgreSQL 18，避免日后为大版本升级导出重建；数据目录以数据页校验和与 builtin C.UTF-8 排序规则初始化，两者初始化后不可更改。

<a id="d-005"></a>

### D-005 Redis 缓存与锁共存时禁止自动淘汰

同实例的缓存、分布式锁与限流计数器不能用 LRU 等自动淘汰，否则锁可能先于业务释放而消失，破坏互斥。使用容量上限与 `noeviction`，缓存靠 TTL 回收，写满显式失败。需要自动淘汰的缓存先隔离到独立实例；逻辑 DB 不能隔离实例级淘汰策略。

<a id="d-006"></a>

### D-006 DDL 是存储契约真源，迁移与字典共同校验

全部 DDL 归 `gr-db`。设计稿表达产品意图，不保证与当前库一致；曾因引用列沿用旧 VARCHAR／UUID 假设造成接口失败，引用主键时须对齐现行 DDL。

迁移以 `file_name + checksum` 记账，内容变化会触发重新应用，因此迁移必须幂等、schema 全限定，不为整理文档修改已记账 SQL。

2026-10-29 用户确认目标是新库，授权将增量结构合入 CREATE：最终字段／约束／索引作为初始化基线，历史编号保留占位，移除旧 schema 改名与旧数据回填／截断。这是一次性例外，不代表以后可改已部署迁移。旧库不就地升级：恢复旧备份后跑 migrate 会按 checksum 重放，形成新旧证据表并存的混合结构，因此迁移改为从 raw 重新入库，源 PG 只在隔离库作对账参照。

数据字典从活库 catalog 生成，并与 canonical contracts、注册表、表归属核对，不手写第二份字段真源；受管 schema 以 DDL 为准，包含 `diag`，排除 TimescaleDB 内部 catalog。新增／修改迁移的注释由门禁校验，存量欠账不阻塞无关改动。

### D-032 V1 封版隔离、反馈分流与 V2 并行演进边界

2026-11-24 用户确认 V1 正式封版并启动 V2 开发，确立以下并行演进边界：

1. **版本与分支隔离**：V1 交付基线由双仓不可变 Git 标签 `v1.0.0`（`getrich@944a192`、`getrich-design@7f57244`）固定，线上服务运行在 `/srv/getrich/current/{app,etl}` 独立发布副本。V2 开发在 `dev`（及特性分支）推进，不得将未验收的 V2 改动随热修带入线上。V1 线上若出现必须立刻修复的缺陷，从 `v1.0.0` 拉出 `release/v1` 分支做最小热修、打 `v1.0.x` 标签部署，再 `cherry-pick` 回 `dev`。
2. **用户反馈四级分流与节奏**：按「主线推进（约 70%）+ 反馈缓冲（约 30%）」并行演进，除 P0 外固定按周集中复盘、不零碎日发——**P0**（阻断／数据口径错误）当日走 `release/v1` 热修；**P1**（高频体验痛点）汇总进 `V1.1` 小版本；**P2**（与既定能力重合）作为 V2 模块排序依据；**P3**（偶发／超范围）记录待观察。
3. **准生产库隔离红线**：云端 `127.0.0.1:5432` 的 `getrich` 库已承接线上 V1 服务与日更，V2 任何新 DDL 迁移、实验写入或破坏性测试必须在本地或独立隔离测试库验收通过并获授权后方可应用于生产库。
4. **V2 优先切入方向**：本阶段先围绕**持仓诊断深化**推进——组合历史回放与 Beta（DS06～DS08）、L4 风险源分解与调仓前后对比；主前端解冻及选股／策略信号按后续批次与用户反馈排期跟进。

<a id="d-030"></a>

### D-030 证券自增 ID 只在单个库内有效，跨库按完整代码映射

2026-11-01 用户确认：`instrument_id` 是库内代理键，不是跨库身份。raw 快照以完整代码 `canonical_symbol` 标识证券，快照 ID 仅保留为来源记录；目标库从同一份 Tushare raw 重建后，自增编号也可能重排，旧 ID 在新库甚至可能指向另一证券。

米筐跨库重放先独立生成「源 ID → 快照完整代码 → 目标 ID」映射文件并冻结 SHA-256，再由导入器显式接受。映射哈希与来源核对状态进入 run／ETL evidence，原 manifest、名单、状态及哈希不改写。完整代码及已有 `meta.symbol_map` 是唯一解析依据；不新增历史别名，不剥前缀匹配六位数字，`unmapped_symbol` 必须与目标 canonical 完全一致。映射必须一一对应，缺失、歧义、合并、拆分或交易所冲突均停止；转换后仍执行原身份校验。

逐代码比较快照与目标的上市／退市日期，差异仅审计，不修改原名单。源库可访问时另核对源 ID 与完整代码；不可独立识别或不可连接时明确记录未核对。工作库写入前须通过备份恢复演练、隔离库映射／逐值／幂等／回滚及覆盖账本重放验收，并取得本轮用户确认；正式风险读取仍受 D-022 约束。

## 接口与选股回测

<a id="d-007"></a>

### D-007 前后端共用实际契约与单一请求层

旧前端类型曾掩盖不存在的响应字段、把成交流水误当开平回合；并行接口层又出现漏认证和重复剥响应信封。前端类型照实际后端响应写，不根据设计稿猜字段或聚合语义；统一请求入口负责认证、401、业务错误与信封，视图转换在消费端完成。接口粒度或枚举未知时先定业务契约，不靠宽泛类型隐藏差异。

<a id="d-008"></a>

### D-008 选股快照与入池日期采用保守历史语义

`pick.batch` 与 `pick.item` 保存上传批次和每日标的池。`strategy_kind` 与业务分类分开，未回填类型的存量策略不自动进入选股列表。CLI 导入没有登录用户或管理导入 job，因此 `uploaded_by` 可空，`import_job_id` 暂不绑定外键。策略引用使用真实主键类型，对外仍用 `strategy_code`。

`pick` 的交易所码 `SSE/SZSE/BSE` 与 `meta` 的 `XSHG/XSHE/XBSE` 不同；关联标的与日历必须统一转换，否则会静默缺失历史关联。

连续导入优先沿用上一交易日 active 批次的 `entry_date`；漏传或日历缺失时保留原值，不重置为今天。偏早的日期可解释、可修正，重置会丢失历史；`product_entry_date` 同理兜底为 `entry_date`。查询优化必须维持漏传、空仓和重新入池的语义。

<a id="d-009"></a>

### D-009 Black-Litterman 保留量纲与观点方向

先验 Π 与观点 Q 分别归一化曾制造数量级差异，使后验压过负观点、产生错误仓位方向。两者保留自然量纲。病态协方差退化时回退为按方向等权；验证必须覆盖非退化数据的后验路径，不能只测相同价格序列触发的 fallback。

未决口径：当前 Ω 取法使 τ 约掉；Q=score 尚未标定成预期收益。调整会改变策略含义，见[待决问题](../../docs/plans/backlog.md)。

## 数据与因子口径

<a id="d-010"></a>

### D-010 因子模型显式保存单位、精度与校准状态

- **现行单位契约（2026-11-09 供应商书面答复，原文 SHA256 `c890ce96b3187ae942beff782b4ac0ff4bf20170e62724981a71f6db56fec6a9`）**：米筐 `v1`／`v2`／`v2trd` 的 `horizon=daily` 公开最终协方差 `F` 为年化口径，特异风险 `s` 为年化标准差；入库时 `F × 10000`、`s² × 10000` 存为年化百分比平方；消费时除以 `10000` 恢复年化小数方差，单日方差再除以 `252` 一次（组合年化方差 $b^\top F b + \sum w_i^2 s_i^2$，单日预测波动率 $\sqrt{\text{年化方差}/252}$），不重复平方、不用非公开辅助矩阵。
- **校验与校准边界**：风险量年化、收益量日频，下游以 `model_run.units` 为准，协方差用双精度。最终预测 `F` 与过去 120 日等权实现方差是不同估计量，RF 比率超限仅作诊断提示、不单独拒绝入库（取代此前 RF 冲突阻塞判据）；RS 原门槛与五件套/身份/结构门禁保持。全区间五表自洽（含 P6 暴露时点、复权与无风险利率书面约定）通过前，全部 `model_run` 保持 `calibrated=false`，下游显式暴露 `degraded/not_calibrated`（2026-10-30 有限样本经验互验见 [iMac 迁移归档](../../docs/history/imac-collector-migration.md#字段互验与补充验证2026-10-30)）。
- **归属与证据域**：`factor.*` 为表级归属（2026-09-18 起归 `ricequant`）；每次日度观测是不可变 run，`available_at` 保守取 raw 实际采集时间，历史回填不充当当时可得数据。风险专用证据表（`dataset_variant`、`import_receipt`、`import_checkpoint` 及校验触发器）归 `factor` schema（037/049），`ops` 保留通用运维；迁移 047 起风险数组严禁空、多维、NULL 或非有限元素。

<a id="d-011"></a>

### D-011 因子矩阵按规范顺序对齐，集合与批次按时期校验

历史样本中，暴露、收益和协方差宽表的因子集合相同但顺序不同；照源列序转数组会得到形状合法、经济含义错误的结果。所有宽表按规范顺序显式 reindex，缺失／重复列拒绝；协方差校验行列标签、对称性和对角元，行业哑变量与 COUNTRY 约束不能用取最大值兜底。

活跃因子集合从当期数据派生并记录 hash，不能把跨 SW14／SW21 的全历史并集当一个模型，也不能把维度固定成所有日期通用。

2026-11-02 用户确认的米筐行业解读边界：已探测历史行业因子口径一致、未观察到切换，但这没有证明它们是当时的行业分类，可能是 2021 版申万向历史回套。回测按行业分组时须按此回溯可能性解读，不能把行业轴一致当成分类 PIT 已获证明。新模型逐月准入必须实际比较行业／完整因子轴，发现变化先留证停止，不自动沿用同一 variant。

（原 D-016）历史全量导入有峰值内存与长事务压力，输入按可独立处理的分区分批，但分批不能改变时序与事务语义：模型集合逐期核验，区间压缩保留跨分区上下文；以实际落库与作业结果验收，不以没有异常日志代替成功。批处理超时单独配置，不放宽交互 API 超时。

<a id="d-012"></a>

### D-012 单表单一来源，跨源映射按主键隔离

- **核心铁律**：不同供应商的单位、复权与缺失口径可能不同，因此同表只允许一个 provider 写入（登记在 `ops.table_ownership`），转移归属须显式执行 `force`/`release`。唯一例外是 `meta.symbol_map`（主键含 `(source, source_symbol)`，各源行互不重叠），不得推广到其他表。
- **历史换码与显示口径（046）**：同一证券在一个来源下可有多个经公告核实的历史代码（不新建第二个证券，不代表代码有效期或 PIT 可得性；一期显示当前代码与名称，输入旧码注明历史别名）。同日重复记录须核心数值严格一致，否则硬失败；仅以下经公告授权的封闭例外允许按新代码保留并写入 `ops.data_quality_check`（`tushare_stock_alias_metadata_override`）：

### D-031 米筐历史风险按缺失原因与次日恢复延迟验收

2026-11-02 用户确认取代 2026-11-01 的经验只数包络：不提高 cap，也不再以缺失只数放行。完整保留历史当日在市名单，不补造数值；模型任一接口整日为空仍停止。其余缺失只要有一只不能由下述四条件解释，就停止当前验收段并报告，既有身份、数值、用途、发布门禁均不放宽。

可解释的 IPO 首日缺失必须同时满足：当日等于该证券冻结的 `list_date`；仅缺 `specific_return`；`exposure` 与 `specific_risk` 均存在；同完整代码在**下一交易日**恢复为 `included`。缺一条件即不属于该例外。前三条件成立但尚未取得次日证据时为 pending，不能记作认可；有次日证据但未恢复则 rejected。通过完整交易日历查询的直接后继确认“下一交易日”，不能使用自然日或稀疏探测日期代替。日 T 的 IPO 缺失验收在 T+1 采集完成后进行；这是历史数据质量复核，不改变原事件时间或数据可得时间。

原始当前／次日观察均走既有严格 raw 读取校验，绑定 manifest 文件字节 SHA-256、语义哈希、观察身份及日历文件哈希，逐证券按完整代码核对恢复；数据库内 ID 仅作来源记录。次日观察仅作该证券恢复的证据，不因而自动接受次日自身。逐日、逐证券及月度按原因汇总，明确 accepted／pending／rejected；重复重判不重复计数，不静默选择替代观察。

旧只数包络、未知原因仅告警、次日恢复只作事后审计的政策不再用于新验收；旧基线、停止证据、validation raw、失败响应与账本原样保留，通过新增独立重判证据记录新结论。2021-12-28 四只已核实 IPO 也必须按新规则重判，不能直接改成“认可”。

历史起点及正式 raw 的条件授权见 D-012；v2／v2trd 须在二分特异风险非空边界之后完成逐月完整五接口样本，接口二分结果不能直接充当已验收模型起点。已批准身份边界仅按 D-012 的完整代码、精确日期与证据处理，其余未知身份仍停止，不以 IPO 例外豁免。本历史 raw 批次采集每天先实查额度，保留 10%（2026-11-02 用户调整）；只有实时确认额度触及保留线才可暂停至下一上海日期并重新查询后续跑，配额不可读或其他失败不得借旧暂停状态自动重启。正式入工作库还须相应 Tushare 股票区间及单位／数值验收完成。

### D-023 停复牌用事件表承载，缺数不冒充停牌

Tushare `daily` 停牌期间不返回行，全天停牌日在 `stock_bar_1d` 中不存在；原 `trading_status` 只能把日内停牌的有成交日标成 HALTED。2026-10-21 改为迁移 044：`market.stock_suspend_event` 保存 `suspend_d` 原始事件（含 `suspend_timing`），`market.stock_suspend_coverage` 保存成功请求日期与 raw 证据，合法空响应也记覆盖；读取时结合交易日历逐日推导状态。交易日既无 bar 也无停牌事件记为未知，不推断为停牌，以免把真实缺数伪装成停牌（PA-12）。

不在 bar 表插入无价格的占位行，那会破坏按 OHLC 非空校验的消费方与压缩统计。事件替换、覆盖写入与 bar 状态刷新同事务提交，较旧观察不能覆盖较新观察；覆盖凭据只证明当前采集，不是 D-022 发布版本或历史 PIT。

状态为 `NORMAL`／`HALTED`／`INTRADAY_HALTED`／`UNKNOWN`：无时段 S 且无 bar、无 R 才判全天停牌；有 bar 的日内 S 保留日内停牌；无时段 S/R 同日等冲突保留未知，不猜先后。缺交易所日历拒绝，不将沪深日历套用于北交所；不据日级状态推断开盘可买性。

BJ 行级待处理（2026-10-31 用户调整，取代此前上市前隔离／停止方案）：北交所不整市场排除，不因成交、换码、list_date 或旧隔离配额停止。只对 `.BJ` 原始观察，将校验失败的那一条转入 `ops.tushare_bj_pending`，不写该观察对应主表；同代码同日期的其他合格观察及其他数据集仍正常入库。股票范围先按 D-029 排除 B 股；范围内沪深校验失败仍整体停止，不因 BJ 例外而放宽其价格、复权、估值、映射或事务规则。坏文件、缺分区、归属冲突、配置、连接及程序错误不属于可继续的 BJ 行级失败。

待处理表由迁移 052 定义，单一来源归 tushare；记录源代码／源日期／可解析交易日、目标及源数据集、原分区行序、失败规则／详情、完整原始值及必要辅助观察、批次和观察指纹。NaN／Inf 用文本标记保留，raw 不改。主表合格写入、待处理写入及 ETL 流水同事务；固定批次加观察指纹 UPSERT，重导不重复增加待处理条数，也不按代码日期整组排除。仅 BJ 行级预检可使用回滚保存点试验真实 DDL 约束，写前同样校验表归属；原始业务键重复的观察先单独验证，避免 keep-last 隐藏坏记录。

历史回补批次固定 `任务名:YYYY-MM`，每月验收后汇报 BJ 待处理记录数、代码数及分数据集数量，写入运行账本、`bj-pending-months.json` 和 NOTES 的“BJ 待处理项，后续单独核实”专属状态行。批次请求日期只校验实际取数范围，不推定为北交所交易日历。回补结束后按待处理代码／日期分布核实历史上市口径、代码变更和复权来源；集中在少数代码时优先查证并修正有误的主数据或历史区间，不长期依赖待处理。原先成交／换码停止条件、20 条累计／5 条单月隔离限额及上市历史否定收据不再作为 BJ 准入前置。

### D-025 原油 TAS 价差与期货绝对价格分开解释

Tushare `SCTAS*.INE` 的 OHLC／前收记录的是相对结算价的偏移量（2025-09-03 low/close 为 -0.1，settle 为 491.8），结算字段仍是绝对价格。依据[能源中心 2023-03-29 通知](https://www.ine.com.cn/eng/circularnews/circular/202303/t20230329_822378.html)，TAS 按当日结算价及其偏移量成交，申报范围为结算价 ±2 元/桶。

raw 按源义保留有符号价差与 NULL，以代码模式加 `exchange=INE, fut_code=SCTAS` 共同识别；不向普通合约放宽价格规则，不向量／额／持仓放宽非负与有限性检查。不能取绝对值、填零或静默加结算价制造绝对 OHLC。普通期货表没有 TAS 价差映射，在另定语义之前 `FutureBars1dImporter` 整行排除 SCTAS 行并计软告警。

2026-11-03 用户核定期货日历：Tushare 在 2010～2014 年（CFFEX）及 2022-12-31（DCE／CZCE／SHFE）漏了部分休市日。仅同时满足“该所供应商记录缺日、同日 SSE 明确休市、该所现有 raw fut_daily 无任何行情、供应商后一个最近开市日的 pretrade_date 等于前一个最近开市日”四项，才推导 is_open=false／has_night=false；SSE 缺日或任一证据不符均停止。raw 原样保留，已有供应商日历行不覆盖，不借此推断开市日夜盘；现有月分区未生成须在无行情证据中明确标注，不冒充整月已采完。仅推导行写既有 meta.trading_calendar，每交易所／日期／规则一条 ops.data_quality_check，四项证据与日历同事务、幂等去重；月报按交易所列推导天数。采集阶段检查整个请求区间、一次性报告所有不可推导缺口；行情采集使用同一内存补全结果。

2026-11-04 用户核定上市前占位行：仅连续合约（不带到期月份）、源 OHLC／结算／前收／前结算七项全缺失、量／额／仓均精确为 0，且当前已采集 raw 中同品种同交易所首个到期月份合约首次出现日严格晚于该行时，才把原跳过行分类为上市前占位。找不到到期合约证据不成立，负数／Inf 经清洗变 NULL 不算源缺失；其他 close／settle 同时无效行即使只有一条，runner 仍停止审核。结构化告警和月账本列代码、日期、品种及 raw 推导上市日，独立月报留完整证据；每行 ops.data_quality_check 与行情同事务、按规则／代码／日期去重，不改 schema、raw、原价格跳过逻辑或补价。2018-08-14 的 TSL.CFX／TSL2.CFX 按 raw 到期合约首日 2018-08-17 核定；以后 IM、TL 等仅满足同样四项时自动放行。

## 持仓诊断

<a id="d-017"></a>

### D-017 缺数据显式不可用，不静默估算

`UnavailableMetric` 没有 value 字段，避免不可用结果被构造成 0；分布无数据返回 unavailable，不用空字典表示“已算过但没有行业”。依赖未启用模块或未确认阈值的检测器返回 `unavailable` 与 reason_code，不以 `not_triggered` 代替，避免缺项被理解成“查过，没有问题”。

2026-10-31 按 PA-02／PA-04／PA-13 修订分母口径，取代原“部分覆盖在已知子集内归一化”的写法：两个分母分开——TopN 以完整输入份额（含未识别代码）为分母，HHI、L1、L2 在已识别子集的计算权重上计算；行业、市值、PB 分布保留 `unclassified`／`missing_or_invalid`／`non_positive` 档，在子集上合计为 1，不剔除缺失后重新归一化。覆盖率＝已识别份额×子集内具备该指标数据的权重，一般指标低于 0.95 降级、低于 0.80 不可用，带缺失档的分布只降级；完整组合模型指标要求全部正权重持仓数据有效。共享载体只存子集结果，阈值在组装时按各请求的输入份额判定，否则“A=100”与“A=50+未知 50”会共用同一状态。量化到 8 位小数后为 0 的持仓按零权重回显，不计入持仓数，但仍属已识别份额。

2026-11-09 用户确认风险计算可用性必须与历史补数分开报告：单日显式请求同一模型、精确数据日期、variant／run，实际回显所用模型与日期及完整非零持仓覆盖；不得回退日期、改用 v2trd 替代缺失的 v2，或删除缺项后重新归一化。有符号权重的覆盖按绝对权重计算，同一 run 的实际暴露／特异风险和 included 账本共同确认覆盖；两种方差单位、因子轴、horizon、校准状态或原子收据与清单不一致即停止预检。历史区间以完整市场开市日历为分母，逐日列缺口，模型起点之前另列，不能只取已有风险行；库存齐全还须逐日持仓证据，不能直接称区间可计算。只读离线 `diagnostic_inputs_ready` 只表示事后研究取数预检，不输出风险值、不代表供应商单位认证／历史 PIT，晚观测时间不能用于更早决策。清单绑定固定源码、数据快照和哈希；旧按月／样本验收与后续逐日 RF 复核须分别标注，未复核不等于通过，不能静默撤销原验收或以库存 accepted 代替新检验。正式 `formal_ready=false`，现有风险入口继续关闭。

2026-11-09 供应商确认复验后，RF仅为诊断，不能继续作为库存或计算取数预检的独立拒绝条件；新83日的实际复核与其他原验收范围明确区分。已补齐的历史缺日应在新快照显示可用库存，仍须按精确模型／日期／run验证实际完整非零持仓；未验收的Nov6即使样本接口恢复，也不能借用11-05或其他模型。清单导出与衍生清单分别固定生产者、完成摘要和输入／输出哈希，不能以读取时的当前哈希反推已验收来源；正式读取和校准限制不变。

<a id="d-018"></a>

### D-018 幂等资源、纯计算缓存与展示状态分离

每次新提交创建新 snapshot；只有同一 UUIDv4 Idempotency-Key 重放同一资源，同键异体返回 409，不按相同请求体永久复用快照。

计算缓存只含规范化的标的、权重等纯计算输入，不含 plan_id、label、intent、覆盖画像或盲点等展示状态，避免跨用户共享缓存串入展示数据；计算载体变更时更新版本。

2026-11-10多用户V1补充：已发布风险计算依赖完整输入分母，缓存身份增加完整正权重份额及未知代码/份额的scope hash；相同已知子集但未知持仓或原分母不同，不共用成功风险载体，仍不把用户ID/label/顺序写入纯计算身份。新载体model coverage以full_input为基准，统一展示helper直接使用，不能再次乘已解析份额；旧无basis载体保留原子集解释。payload版本7.1隔离旧缓存，unknown20%必须在risk coverage与data_quality均显示80%、完整风险不可用。

A–E 显式区分 ready／unavailable／failed，报告与数值基于同一组固定运行结果。失败方案保留输入与安全错误，新快照重试不改旧终态；零权重校验先于可解析子集过滤，并保留完整输入回显。

<a id="d-021"></a>

### D-021 诊断计算放在 gr-api 内的纯计算模块，组合回放另写

2026-10-21 确认：一期的协方差、风险贡献、L3／L4、回放、VaR／CVaR、Beta 等计算放在 gr-api 内的独立模块，只依赖 numpy／polars／gr-tools，不查库、不 import API 与数据接入代码，由静态测试守卫；`services/diagnosis.py` 只负责取数与组装。公式因此可对照手算案例单测。暂不新建包，需要时再抽出。

模型口径实现（2026-11-01）：最小扭转按设计在标准化空间交替求正交 Procrustes 解与对角缩放，原空间 `t = σAσ⁻¹`，暴露同步转换 `ẽ = t⁻ᵀe`，风险源方差合计须与组合因子方差相对误差不超过 1e-8，否则 L4 不可用；因子相关矩阵最小特征值不大于 1e-12 时拒绝正交化，不做截断或正则化。这些容差只判定数值可算性，真实数据阈值待复核。PA-13 阻断分两层：缺模型数据的持仓在共享载体中即使完整组合指标不可用；未识别份额只在组装时按当前请求阻断，避免跨用户缓存串入覆盖率。

历史收益掩码（2026-10-31）：日简单收益用 `close × adj_factor`，只在相邻两个开市日都可交易且有价格时计一个收益；全天停牌、跨停牌复牌收益和 D-023 的 UNKNOWN 缺口一律剔除，不补值、不跨缺口。日内停牌（INTRADAY_HALTED）当日有真实收盘价，用户确认计入样本。D-023 四态在纯计算模块另写一份以免请求路径引入 pandas，测试对 gr-data 的 `resolve_trading_status` 全部 32 种组合逐值核对，改规则须两边同步。交易日历在区间内缺行时历史指标不可用，不把缺行当相邻开市日。

组合回放（PA-12）新写，不复用 gr-backtest：后者在分红到账、小数股、涨停不买次日重试、现金预留、退市终止和分开记账等撮合语义上不支持或做法相反，还会带入 pandas、matplotlib 等依赖。只借用日线时区钉法等零件。

<a id="d-022"></a>

### D-022 数据版本是发布清单，由 gr-data 发布

`diag.data_version` 的每个版本是一份发布清单：记录发布时刻与 `available_options`，逐数据集钉住数据日期与组成版本（导入收据或代际 ID；米筐钉住具体 run_id）。缓存隔离与重算的“未被修订”判定比较组成版本，不扫业务表算内容哈希；诊断取数以发布时刻为截止，不用 `now()`，否则同一版本下不同报告会读到不同数据。版本由 gr-data 在数据导入并通过质量检查后以独立步骤发布，诊断只读，不在 API 启动或 worker 中调度。

一期轻量限制（2026-10-23 用户确认）：只诊断最新日，暂不建可变数据版本表。组成收据一旦变化，旧版本标为已修订、不可复算，需发布新版本，不能回退读取最新数据冒充原版本；按发布时刻过滤无法恢复已被 UPSERT 覆盖的数据，所以历史报告保留计算产物但不承诺重算。诊断专用数据库角色延后。失效与组成写入须原子衔接，统一读取在一致性快照内核对当前收据。

发布门槛：complete × 1000 ≥ candidate × 999（candidate > 0），身份及上市边界未知为 0；组合层要求全部非零持仓的所需数据完整，缺失按 D-017 不可用。validation 用途永不原地转正，production 使用独立 variant；数据库约束／触发器拒绝发布明细引用 validation run。

- **协议与迁移演进（049 / 054～057）**：

### D-020 mock 认证默认关闭，无效 JWT 不回退请求头
